# 轻小说书架（分享版 · 2026-10-22 v5.0.0-alpha.11）

这是「找书 → 按需翻译 → 本地书架网站」的干净代码包。  
**不含**译本、书架/阅读进度、收藏、反馈、口味画像、推荐缓存或任何 API key。

## 30 秒跑起来

需要 **Python 3.10+**（只用标准库，不需要 pip 安装依赖）。

### Windows

```powershell
cd lntrans
$env:PYTHONUTF8 = "1"
python run_selftests.py
python lnserve.py --port 8099
```

### Linux / macOS / Android 容器

```bash
cd lntrans
python3 run_selftests.py
python3 lnserve.py --port 8099
```

然后浏览器打开 **http://127.0.0.1:8099/** 。

`run_selftests.py` 会启动隔离数据根和本地桩模型，不联网、不调用真实 LLM，
也不会碰真实书架数据。看到「全部 33 个自检通过」才算环境正常。

## v5 数据根（可选，推荐长期使用）

v4 目录仍可直接运行。v5 在设置 `LNTRANS_HOME` 后使用单一代际数据根，
并通过系统级排他锁阻止两个进程同时写同一份数据：

```bash
python3 lnmigrate.py migrate --home /data --source-root . --source-profile ../lnfinder
python3 lnmigrate.py migrate --home /data --source-root . --source-profile ../lnfinder --write
LNTRANS_HOME=/data python3 lnserve.py --port 8099
```

默认第一条只做空间、文件和目录检查；第二条才复制并校验，最后一次性切换
`active_generation`。旧目录不会被删除。详细契约见 `docs/V5-DATA-SAFETY.md`。

变更型 `lntrans.py` 命令、`lnbackup.py export` 和 `restore --write` 与
`lnserve.py` 共用同一把数据根锁。运行它们前先停止书架服务；只读的
`status` / `list` / `verify` / 干跑命令不占锁。服务内备份的在线一致性和
维护脚本边界见同一份数据安全文档。

## 润色（可选）：把"机翻味"磨掉

```bash
python3 lntrans.py polish <slug> --chapter 12        # 干跑：只看前后对比
python3 lntrans.py polish <slug> --chapter 12 --write # 落盘（自动备份）
python3 lntrans.py polish <slug> --all --budget 40000 # 批量，带 token 上限
```

只润色 ≥24 字的段；**改写表达不改事实**——对白数变了、术语表里的译名丢了、
长度离谱、混进英文/日文，任何一条不过就保留原译。失败不重试、不二分。

## 接入新书的 SOP：人名一致性（强烈建议每本都跑一遍）

翻译是逐 chunk 请求的，模型每次独立决定译名 —— 同一部作品里一个人名被写成
两三种样子（实测一本里 ローラ 被译成「萝拉」70 次、「罗拉」50 次、「劳拉」5 次）
是常态。这套流程把它变成可验收的步骤：

```bash
cd lntrans
python3 lntrans.py names <slug>          # 1) 找"一名多译"（一次 3~4k token）
grep -ro "译名" novels/<slug>/chapters/ | wc -l   # 2) 用实数核频次（模型报的数不可信）
python3 lntrans.py learn <slug> --term "日文名=选定译法"   # 3) 锁进术语表
python3 lntrans.py fix <slug> --rename "旧译名=新译名"      # 4) 清存量（不花 token，自动备份）
python3 lntrans.py names <slug>          # 5) 复核到 0 冲突
python3 lntrans.py residue <slug>        # 6) 看残留假名
```

三条不要动（否则会毁语感或白改）：
* **称呼后缀**：千岁 / 千岁酱、奏 / 奏前辈 —— 那是原文在变称呼，不是译名不统一；
* **子串**：贝尔贝特 / 贝尔贝 —— 后者是前者的前缀，不是第二种译法；
* **全称/简称**：波特曼伯爵家 / 波特曼家。

`residue` 也能兜住"译文夹日文"（引号内的刻意引用、颜文字、装饰性浊点/长音符不算；
加 `--context` 会把每一处残留连同上下文打出来）。

## 这一版的变化

- **v5.0.0-alpha.11：本地 EPUB/TXT 导入 + 术语过期重翻**（学自 auto-novel）：
  - 首页/设置页「导入本地 EPUB / TXT」或 `lntrans.py import <文件>`：建书后自动
    进书架「想读」，之后仍走「读到哪翻到哪」。同一文件重复导入不会建第二本。
  - 术语表改过之后，`stale <slug>` 只列出**真的用到该词**且边车指纹变了的章节
    （默认只报告、0 token）；阅读页也会给本页章节一条提示，可一键重翻本章。
  - `terms <slug>` 按片假名频次找候选术语（0 token）；`titles` 对 `第12話`/`閑話`
    这类标题直接规则翻译，同名标题只翻一次。
- **v5.0.0-alpha.9：修「翻译卡了」的两个真原因**（有线上证据，不是猜）：
  1. **预算用尽没有可见出口**：自动请求现在返回 `409 budget_exhausted`，阅读页横幅
     直接给「去提高预算」；`/queue` 有一键 +5 万/+10 万。默认预算提到 30 万/天。
  2. **废弃的 `translate.enabled` 还在当闸门**：阅读页 tick 不带 ceiling 时，
     worker 走旧 `auto_ceiling(enabled)` → 上限 0 → 生成一条 `done` 的
     「此书未开启翻译」空任务（界面＝点了没反应）。现在**任何入口不给 ceiling
     就默认翻到全书**，旧开关彻底不参与判断。
  - 顺带：已译完的书不再占「正在翻译」位置；`/api/job` 不再被当作"在读信号"
    （查状态会把书误标成在读）；打开但没读（进度 0）的书不自动开翻。
- **v5.0.0-alpha.10：预算改成「提醒」而不是「刹车」**。alpha.9 里预算用满会停，
  实际使用中就是"读到一半又卡了"——为继续读只能反复加额度。现在超预算只提示
  （阅读页/翻译列表显示已用多少），**在读的书继续翻**；硬停只有「全局暂停」
  和「暂停本书」，预算填 0 = 不限。

- **v5.0.0-alpha.8：翻译调度重做**（`lnsched.py` + `/queue` 翻译列表）。
  旧模型「自动翻译开关 + 读到 + N 章」有两个结构性问题：读者连读几章必然断粮
  （"翻译跟不上阅读速度"），想提前攒书也没有入口。现在：
  - **在读就一直翻**：打开/翻页/轮询都会刷新"最近在读"，30 分钟没动才停（可调）；
    不再有 N 章上限，读到哪翻到哪，翻完整本自动停。
  - **翻译列表**：`/queue` 可把书加进来按顺序提前翻（详情页也有「加入翻译列表」）。
  - **每日 token 预算**（默认 30 万）+ 全局暂停：没人在读时不会无限烧钱。
  - 停止按钮 = 暂停这本书（不会被下一次轮询自动恢复）；继续 = 显式恢复。
  - 策略是纯逻辑模块 `lnsched.py`，`test_sched` 用 30 条断言覆盖
    （在读/空闲/队列顺序/译完/暂停/预算/跨天/持久化/坏状态/HTTP 操作）。
  - 顺带修：轮询每次都 fsync 调度状态（改内存，打开页面才落盘）；
    已读完/已弃文不再自动翻；调度线程不在自检服务里跑（避免测试竞态）。

- **v5.0.0-alpha.7：修两类「翻译卡住」的真原因**（都是实际踩到再修的）：
  1. **装饰段落拖垮整章**：`――――――` 这类分隔线被送给模型 → 照抄回来 →
     「输出必须是中文」判失败 → 重试 3 次后整章不落盘（实测白烧 4.7k tok）。
     现在 `has_translatable()`（假名或汉字）判定：纯装饰段 0 次请求直接穿透，
     混合段按索引穿透、不计「未译全」。
  2. **重启吃掉正在跑的任务**：服务启动时会把 running 标成 interrupted（安全设计），
     但没人接回来，用户看到「又卡了」。现在启动后自动续跑一次：只认「因重启中断」、
     只续书开着自动翻译的、剩余 ≤10 章、上一条不是自动续跑（`LNTRANS_NO_AUTO_RESUME=1` 可关）。
     顺带修掉：被取代的 worker 收尾时记录永远停在 running（`_close_own_record`）。
- 诊断工具：`py-spy dump --pid <pid> --nonblocking`、`kill -USR1 <pid>`（写全线程栈到日志）、
  心跳停 120s 自动 dump。

- **v5.0.0-alpha.6：修一个跨平台路径 bug**。`record_backup()` 只保留文件名，但
  Windows 的 `C:\dir\x.zip` 在 POSIX 上 `os.path.basename` **不切分反斜杠** ——
  宿主机绝对路径被写进数据根状态文件，违反"备份身份不含宿主路径"的约定
  （`test_data_safety` 当场红）。现在先 `replace("\\", "/")` 再取 basename。
  同版本内还合并了 v4.8~v4.10 的变更记录（去重 v4.9 两处重复）与文档更新。

- **v5.0.0-alpha.5：单一代际数据根 + 进程排他锁**（`lndata.py`）。设 `LNTRANS_HOME`
  后数据在 `<home>/generations/gen-*/` 下，`.lntrans-state.json` 是唯一的指代指针
  （迁移=复制校验完再原子换指针，回滚=把指针换回去，**不重命名数据目录**）。
  `lnserve.py` 整个生命周期持有 OS 排他锁；变更型 `lntrans.py` 命令、`lnbackup.py
  export`、`restore --write` 共用同一把锁 —— **服务在跑时这些命令会被拒绝**（提示先停
  服务）。只读命令（`status`/`list`/`lessons`/`residue`/`verify`/干跑）不占锁。
  不设 `LNTRANS_HOME` 时旧 v4 目录照常可用。
- **章节边车**（`chapters/NNNN.meta.json`）：记录原文/译文 SHA-256、模型与 prompt 版本、
  token 与成本、未译全段落。写入顺序是"先装边车、再原子替换正文"——中间崩溃会留下
  显式 hash 不匹配，读端把这章当**不可用**并重译，绝不把混版本当成品。v4 旧章节没有
  边车也能读。
- **可恢复的翻译任务**（`lnjobs.py`）：任务落 `data/jobs/*.json`，八种状态；启动时把
  遗留的 `queued`/`running` 标成 `interrupted`，**不自动重放**（花钱的事等用户点确认）。
  单条任务记录损坏 → 只读恢复模式：书架/阅读/进度/备份照常，翻译写入回 503，
  坏文件隔离到 `data/jobs/quarantine/`，**绝不静默删除**。
- **契约层**（`lncontracts.py` + `contracts/*.schema.json`）：章节边车与任务记录有 JSON
  Schema；`dir_sigs()` 一次 scandir 拿齐 (mtime, size, inode)，首页 30 本 × 200 章
  实测 320ms → 62ms。文件哈希缓存带 inode + 写端显式失效，防 exFAT 2 秒 mtime 粒度
  导致的"写完了还是旧缓存"。
- **模型配置统一**（`lnmodels.py`，见 `docs/MODEL-CONFIG.md`）：端点与 key 用
  `LNTRANS_LLM_BASE_URL` / `LNTRANS_LLM_API_KEY`（旧的 `LNTRANS_LLM_BASE` 仍是别名）；
  模型按角色选：`translate` / `auxiliary` / `review` 三个 `LNTRANS_MODEL_*`，
  `LNTRANS_MODEL` 兜底，CLI `--model` 覆盖单次调用。回环端点可以不带 key。
- **局域网改为表单登录**（`lnserve.py`）：绑非回环地址时给地址+口令、网址不再带 token；
  平板输一次，之后只存随机会话 Cookie。写请求校验同源 + Host 白名单

- **分享包改白名单构建**（`make_share.py`）：只装 `INCLUDE` 里点名的文件，
  `lntrans/novels/`、`lntrans/data/`、`lnfinder/reports/`、`-中文.md`、`.pyc` 按前缀/
  后缀双重排除 —— 以前是"手工 zip + 文档里的排除清单"，真实画像和 11 个 `.pyc`
  就这么进过评审包。
- **自检 22 → 29 个**：新增 `test_covers` / `test_contracts` / `test_data_safety` /

- **v4.7：修「翻译卡住，第 x 章和段进度互相抢显示」的真根因**。旧的中文判定是

  整块译文就被判成"没译成中文"，于是反复重试 + 二分，某章烧了 **19 次请求 / 38,420

  并在重试提示里点名哪几段有残留 —— 同一章降到 **1 次请求 / 2,887 token**。
- **v4.7：给重试加上硬上限**，不再有"越修越贵"的可能：单章调用次数（64）、二分深度
  （4）、单章 token 预算（`LNTRANS_CHAPTER_TOK`，默认 30000）三道闸；预算耗尽时
  返回当前最好的结果并标 `partial`，不再是无限重试。每次护栏触发都写一行
  `[trans_guard] {...}` 结构化日志，事后能查是哪一段、烧了多少。
- **v4.7：`names` 重写**。旧版靠后缀/相似度启发式，一部书能吐出 2173 个"疑似一名
  多译"（真冲突只有几个），淹掉了真问题。现在改成让模型一次性抽取人名+译法，再用
  字面频次采样核实（模型报的次数是幻觉：它说 15/5，实测 103/17），并过滤敬称后缀、
  子串、全称/简称三类假冲突。
- **v4.7：`polish` 可用且安全**（见上节）。实测 8 章 164 段、约 4 万 token；
  对白数、引号数、行数逐章核对不变，字数波动 ±1%。
- **v4.7：`residue` 成为可信指标**：引号内的刻意引用、颜文字、装饰性浊点/长音符
  都不算残留（否则指标永远假红 = 等于没有指标）；换行/引号这类只在 `--context` 里看。

  缺了服务会直接起不来**。

  - 阅读页新增「**前情 · 人物**」折叠块：上次讲到哪（最近两章梗概）、这几个人是谁

## 备份 / 恢复

译文能重译（花时间花钱），但口味画像里的"当时为什么喜欢"和阅读历史重建成不了。
换机器、重置容器、升级前，先留一份：

* 网页：首页最下面「数据备份」→「⬇ 下载备份 zip」。
* 命令行（`--out` 指到容器外的目录才叫备份）：

```bash
cd lntrans
python3 lnbackup.py export --out ~/Download       # 约 5 MB / 无数据时几 KB
python3 lnbackup.py verify ~/Download/xxx.zip     # 逐文件核 sha256
python3 lnbackup.py restore ~/Download/xxx.zip     # 干跑：先看会新建/覆盖什么
python3 lnbackup.py restore ~/Download/xxx.zip --write   # 真恢复
```

装的是 `novels/`（译文/原文/缓存）、`data/`（书架/书库/阅读历史）、`lnfinder/`（画像）；
`*.log`、`*.tmp`、`__pycache__` 不装。恢复**只增不删**：本地多出来的文件不动，
同名但内容不同的先改名成 `.bak-<时间戳>` 再写 —— 误操作最多多几个 `.bak`。
恢复后重启服务（进程内缓存要重读盘）。
