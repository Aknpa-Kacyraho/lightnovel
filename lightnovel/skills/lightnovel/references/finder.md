## PART A：找书与个性化推荐（lnfinder）

用上游源站的公开标签/榜单数据发现并个性化推荐轻小说（尤其是不出名但有对口标签的作品）。
当用户想找新轻小说、问「最近有什么好看的」「推荐几本」「按标签找书」、想追踪某部作品更新、
或抱怨通用 AI 只推大热作品时用这一 part。

本 part 覆盖：推荐规则、打分与画像机制、IDF 加权相似度、负反馈归因、隐藏语义、
子命令表、日文标签对照、数据源与限制、标准工作流、以及一堆踩过的坑。

### 自检怎么跑（改完必跑）

```bash
cd <工具目录>/lnfinder && python3 selftest.py        # 推荐规则 / 误匹配 / 权重折扣
cd <工具目录>/lntrans  && python3 run_selftests.py   # 一键全跑（35 个）+ 残留与指纹断言
```

工程铁律（每条都是真 bug 换来的）：

1. **写自检脚本，不要靠脑子想**。这个项目的真 bug 基本都是自检抓出来的。
2. **跑完必须断言环境干净**。`run_selftests.py` 会比对跑前跑后快照，
   并**按命名规则**识别自检产物（`__*` / `book0*`），不是只比差异。
   * 踩过：`ignore_errors=True` + 变量被覆盖 → 清理**静默失败**却照样打印"已清理"。
     清理目录要用独立变量，并 `assert not os.path.exists(...)`。
   * 踩过：把"跑前就存在的残留"当合法基线 → 断言抓不到泄漏。
3. **测试写错时别改代码**。先判断是代码错还是期望错。
4. **测试要调生产函数**，别在测试里重拼一遍逻辑。
   * 踩过：测试自己拼了 `should_watch(status)` 却漏传 slug，休眠规则压根没被测到。
5. **别写死日期**：用 `time.time() - N*86400` 相对计算，否则测试会随时间失效。

### 推荐规则（别搞错）

**命中一个偏好就可以推荐，多命中只是分更高 —— 绝不要求全部命中。**

理由：要求全命中会把范围砍到几乎没货，还会丢掉「只对上一个口味」的好书。
读者的原话基本是这个意思：「满足我喜欢的特性一个就可以推荐，当然多匹配最好，
但不一定非要我要求的特点都要，那种作品可能就没有。」

体现在代码里：

* `score_work` 只要求 `len(hits) >= 1`；**没有偏好命中**才不推荐。
* 结果**分层展示**（`--tier`，默认开）：
  * **A 档**：命中 ≥2 个偏好，按分数排 → 「最对味」
  * **B 档**：只命中 1 个，**按评价点排** → 「窄但可能更惊喜」
    （单命中分数天然低，若按分数排会被埋在几十名外，宝藏就看不见了）
* B 档有质量门槛（`weak_hit_min_score` / `weak_hit_min_points`）：
  只碰到 `ざまぁ`(+2) 这种弱标签的作品要剔除，除非分数够高或评价点极高。
* 只命中 ≤2 个偏好的作品，套路惩罚额外打七折 —— 别让套路扣分把单命中的好书挤出榜。

`--all-of A B C` 是**硬性全命中**，只在用户明确说「我就要同时有这几个」时才用。

### 核心思路（为什么它比问通用 AI 好）

通用 AI 推荐轻小说时只能背出热门作品，因为它在回忆「知名度」。
但真正决定一本书合不合口味的，是**标签组合**（ざまぁ / 追放 / チート / 悪役令嬢 /
もふもふ / スローライフ …）。上游源站把标签公开、可搜，于是可以：

1. 按你喜欢的标签去搜，直接捞到**冷门但对口**的作品；
2. 用多标签加权打分排序；
3. 用「最少命中标签数 / 负标签黑名单 / 评价点下限」过滤掉噪音。

所以推荐依据是「标签对不对口」，不是「火不火」。

#### 首次使用必改：代码里的默认画像和默认搜索词

`lnfind.py` 的 `DEFAULT_PROFILE`（内置偏好标签与权重、`formula_tags`、
`misunderstanding_tags`）以及 `scan` 不传词时用的那组默认搜索词，
都是**原作者按自己口味写进去的示例值，不是通用默认值**。第一次用之前先按自己的偏好改掉：

* 把 `DEFAULT_PROFILE` 里的偏好标签/权重换成自己的；
* 把 `scan` 的默认词表换成自己想挖的方向，否则 `scan --report` 只是在挖别人的口味；
* 改完先 `profile` 看一眼画像，再 `recommend`。

（也可以完全不改代码，直接用 `learn --like` 把默认值覆盖掉；但没被显式覆盖的标签
会一直带着别人的默认权重，所以更干净的做法是先把默认值改对。）

### 子命令

| 命令 | 用途 |
|---|---|
| `profile` | 查看当前偏好画像 |
| `learn --like ざまぁ 追放 --skip ハーレム` | 调权重 / 拉黑标签，**这是个性化的关键** |
| `recommend --top 20 [--report]` | 按画像抓取并推荐，`--report` 出 Markdown |
| `recommend --pool --top 10` | 不重新抓取，用本地候选池 |
| `recommend --tag ざまぁ` | 只保留含某标签的 |
| `new --days 30 --top 15` | 近期有新章/新作（追更新） |
| `author レオナールD` | 找某作者的作品 |
| `interesting --min-count 3` | 统计候选池标签频次，发现还没加进画像的口味标签 |
| `scan [搜索词…] --report` | **稀缺口味的正确挖法**：一次扫多个描述性搜索词。见下 |
| `like "<标题或URL>"` | 喂一部看过的作品，按标签**自动加权**画像（核心的持续优化入口） |
| `dislike "<标题或URL>"` | 喂一部不喜欢的，自动降权 |
| `import <文件> [--dry-run]` | 批量导入看过的书（txt 一行一本 / epub 取文件名 / **novelia 收藏 JSON**） |
| `history` | 看画像的学习轨迹，知道每个权重是怎么来的 |
| `feedback "<标题>" "太公式化了" [--yes]` | **自然语言反馈**：先预演，确认后才写。见下 |
| `clinic` | 口味诊所：统计喜好与标签的相关性，样本≥6 才给结论 |

### 稀缺口味怎么挖（重要）

站内标签往往太宽泛。例：中文说的「误解系」（代表作《陰の実力者になりたくて!》/暗影大人）
在 Kakuyomu 的对应标签是「勘違い」，但搜出来的**一半是后宫喜剧**，不是真误解系。
这时不要死磕一个标签，改用 `scan` 扫一组**描述性搜索词**：

```bash
python3 lnfind.py scan --report   # 不传词就走代码内置的默认词表（原作者口味，先按自己的偏好改掉）
```

打分器里有两个针对性的机制（在 `DEFAULT_PROFILE` 里）：

* `formula_tags` —— 公式化套路字典（異世界転生/ハーレム/追放/ざまぁ…）
  命中就扣分，用来压掉「看多了要死人」的流水线作品；
* `misunderstanding_tags` —— 若作品含误解系标签，套路惩罚只按 **30%** 计
  （因为误解系本身就常套着异世界壳子，不能一刀切）；
* 另有「辨识度加成」：画像与套路字典之外的标签越多，分越高（鼓励新鲜感）。

用户的偏好偏「反套路」时，就调大 `formula_tags` 的数值；
偏「爽就完了」时，把 `formula_tags` 清空即可。

#### 技巧：交叉标签比单个标签准得多

用户口味往往是**多个维度的交集**。示例：某用户要〈维度1〉+〈维度2〉+〈维度3〉+〈维度4〉，
这时不要分别推荐，而是让它们交叉：

```bash
# 精确交集（本地筛选，对应站点语法里的 标签$）。把 <标签A>… 换成自己那几个维度对应的日文标签
python3 lnfind.py recommend --all-of <标签A> <标签B> <标签C> --top 10
# 或者用组合词扫（站内存在 TS百合 / 百合コメディ 这类把两个词直接拼起来的组合标签）
python3 lnfind.py scan <组合词1> <组合词2> <关键词3> --report
```

交叉后候选会变少但命中率极高 —— 这正是通用 AI 做不到的地方
（它只会给你「异世界 + 后宫」这种最大公约数）。

### 持续优化画像（越用越准）

这是本 part 最重要的部分。**不要靠一次性猜口味，靠用户的真实阅读记录慢慢长。**

```bash
python3 lnfind.py like "<看过的书名>"                          # 喂一本，自动加权它所有标签
python3 lnfind.py import my_favorites.json --dry-run           # 先看匹配对不对
python3 lnfind.py import my_favorites.json --weight 0.4        # 确认后真正写入
python3 lnfind.py history                                      # 回溯画像怎么长出来的
```

设计要点（改代码时别破坏）：

* **步长很小**（like 默认 0.6，import 默认 0.4），避免一本带偏整个画像；
* **套路标签只按 40% 加权**（`learn_from_work` 里的 `dampen_common`），
  否则读几本异世界之后 `異世界転生` 会淹掉那种真正有辨识度的偏好；
* **同一部作品只学一次**（`already_learned` 查 `history.jsonl`），重复喂不会让权重膨胀；
* **画像要能「自升级」，不许一次定死**：人是会变的。已内建**时间半衰期衰减**
  （`apply_time_decay`）：每次写入画像前把长期没被触碰的权重向中性 1.0 收缩
  （`w ← 1.0 + (w-1) × 0.5^(elapsed/90)`，半衰期 90 天；间隔 <12h 不动），
  旧偏好自然退场、近期信号占比更大；总在 reinforce 的标签稳定在偏好位。
  `blocked_tags` / `formula_tags` 数值不衰减。任何后续改动都要给画像留**持续进化**
  的空间（如按样本再衰减、调半衰期），别让初始偏好永久主导；衰减/调整同样写进
  `history.jsonl`（`decay` 事件），可回溯；
* **宁可拒绝也不误匹配**：`resolve_work` 只在精确或子串命中时才返回，
  否则打印最接近的候选让用户确认。**绝不能返回第一条搜索结果** ——
  用错作品的标签加权会静默污染画像（这个 bug 修过一次，别改回去）；
* 每次改动都写进 `history.jsonl`（只增不改），可追溯。

#### 用户口语反馈怎么处理（重要）

用户最常见的反馈形式是随口一句：「那本太公式化了」「这本后宫太多，不行」
「TS 那本挺对味」。**千万不要把整本的标签一起降权** ——
那会误伤用户真正喜欢的东西。假想示例：某本书里读者喜欢它的 `学園`/`日常`，
但不想要 `ハーレム`，若整本降权就会把 `学園`/`日常` 一起拉低。

正确做法是用 `feedback`，它按**用户说的原因**把改动收敛到相关标签：

```bash
python3 lnfind.py feedback "<标题>" "后宫太多"           # 只降 ハーレム
python3 lnfind.py feedback "<标题>" "太公式化了" --yes    # 只降套路标签（按 40% 计）
python3 lnfind.py feedback "<标题>" "不对味" --only <标签A> <标签B> --yes   # 手动指定
```

要点：

* **不加 `--yes` 只预演，不写任何东西**。所以可以放心先跑给用户看。
* 预演的数值必须和实际写入**用同一个公式**（含套路标签的 40% 折扣），
  否则预演会骗人（这个不一致修过一次，别改回去）。
* 识别不出具体原因时**不要瞎猜**…… `feedback_targets` 会退回套路标签；
  但如果作品身上根本没有那些标签，就应当如实说「没法定向」，
  并建议用户用 `--only` 指定，而不是硬改一个不相干的标签。
* 攒够样本后用 `clinic` 看相关性；**样本 <6 不要下结论**，
  小样本相关性多半是巧合，据此大改权重的代价很高。

#### 怎么拿到用户的阅读记录

* **novelia 收藏导出**（最权威）：`GET /api/user/favored-web/default`
  或 `/api/user/favored-wenku/default`（需带 Bearer token），
  返回的 JSON 直接丢给 `import` 就能解析（认 `titleZh`/`titleJp`/`title` 等字段）。
* **txt 清单**：一行一本，`标题 | 作者 | url` 也能认。
* **epub**：从文件名取书名。
* 注意：跑在受限容器里时（例如手机上的 proot），通常**读不到宿主机的
  `/sdcard`**，没有无障碍服务也读不到屏幕。所以**不要承诺「自动读取手机阅读记录」**——
  让读者把清单或导出文件给过来，用 `import` 吃进去。

### 标准工作流

1. **先建画像再推荐**，否则只是通用口味。
   最优先：让用户 `import` 收藏导出或 `like` 几本看过的书（真实信号）；
   其次：先跑 `recommend` 给他看，根据他的反馈 `learn`（手动信号）。
2. 用户说「我想要 X 那种感觉」→ 把这些感觉翻译成日文标签（标签是日文的！），
   用 `learn --like` 加进去，再 `recommend --report`。
3. 用户说「最近有啥新书」→ `new --days 14`。
4. 用户说「这作者的其它书」→ `author <作者名>`。
5. 推荐结果里**务必带上命中理由**（哪几个标签加了多少分），这样用户能判断并反馈。

### 数据源与限制

* **Kakuyomu**（`kakuyomu.jp`）：搜索页 `/search?q=<标签>` 的
  `__NEXT_DATA__` 里带 Apollo 状态，含标题、类型、`tagLabels`、作者、
  评价点、章节数、字数、首次/最新发布日。**这是主力数据源。**
  注意：标签页 `/tags/<标签>` 是 SSR，没有 `__NEXT_DATA__`，用搜索页代替。
* **成为小说家吧**（`api.syosetu.com/novelapi|novel18api/api/` + `ncode.syosetu.com`）：
  发现（`lnlib.syosetu_rankings()` / `syosetu_search()`，一般向 + R18）、上架
  （`/api/add` 接受 `ncode.syosetu.com/<ncode>/`、`novel18.syosetu.com/<ncode>/` 或裸
  ncode）、抓正文（`lnlib.syosetu_work()` / `syosetu_episode_text()`）**都已接通**，
  和 Kakuyomu 一样能加入书架、翻译、阅读。三个坑：① 页面要求完整浏览器头
  （`lnlib.syosetu_headers()`），少 Accept 就 403；② R18 要 `over18=yes` cookie；
  ③ 本机/部分网络对 syosetu 的 DNS 可能不通，需要时给服务进程设 `HTTPS_PROXY`
  （代码不写死代理）。
  短篇没有话链接（正文就在作品页），`syosetu_work()` 会当成第 1 话；章节页的
  `--preface` / `--afterword` 不是小说内容，解析时已排除。
* **不要**去抓 `n.novelia.cc`：该域名在国内被 SNI 阻断（详见项目 README 的分析）。
  本工具刻意绕开它，直接打上游。

### 注意

* 标签必须是**日文原文**，中文标签搜不到东西。
* 豆瓣/贴吧式的「口碑」不在数据里，只用源站的客观指标（评价点、字数、更新日）。
  不要替用户编造内容评价。
* 尊重源站：默认每次请求有缓存，`--pages` 不要开太大。

### 相似作品：用 IDF 加权的标签重合，别数标签个数

想给「这本还有没有类似的」找候选时，**不能**按「重合标签个数」排序：
`異世界 / 転生 / 主人公最強 / チート` 这类大词几乎人人都有，
谁重合得多谁排前面 → 推出来的是「最热门」，不是「最像」。

做法（已实现在 `lnserve.similar_works`）：给每个标签按 `log(1 + N/df)` 加权，
`df` = 池子里有多少本带这个标签。于是重合一个冷门标签
（`勘違い`、`悪役令嬢`、`おっさん主人公`）比重合三个大词更能说明味道相同。
同作者再给一个小加成。

经验值：低于约 0.9 分就不算「相似」，**宁可少给也别硬凑满 N 本**。
自检用合成池钉死这条：造一个「重合 1 个冷门标签」和一个「重合 3 个大词 +
999999 评价点」的候选，断言冷门那个排在前面（否则排序会退化成按热度）。

### 负反馈要**归因**：原因决定扣哪些标签

「不感兴趣」只写一个布尔值就浪费了。同一本书，用户不满的原因不同，
该扣的标签完全不同 —— 实现里 `reason` 映射到不同的权重和标签集合：

| reason | 权重 | 扣哪些标签 |
| --- | --- | --- |
| `theme`（这种题材我不看） | 0.8 | 这本书的全部标签 |
| `cliche`（太套路了） | 0.4 | **只扣套路标签**（画像里的 `formula_tags`） |
| `meh`（就是不感兴趣） | 0.25 | 全部标签，轻扣 |
| `author` | 0.5 | 全部标签 |

`cliche` 这条最关键：读者嫌「套路」时，要扣的是 `異世界転生` 这类大词，
**绝不能连带扣掉 `勘違い`、`悪役令嬢`** —— 那恰好是想要误解系的人的核心偏好，
误伤一次画像就歪了。没有命中任何套路标签时，降权要更轻（0.2），因为无从归因。

另外：同一本书只学一次（`already_learned`），重复点不能反复扣，
否则标签会被越扣越低直到归零。

### 隐藏必须在**所有**列表里生效

「隐藏/不感兴趣」只过滤一个列表 = 用户眼里「点了没反应」。
数据层要让 `cached()` 默认就排除隐藏项（而不是只过滤书库列表），
同时保留 `include_hidden=True` 给「按 id 找元数据」的路径用 ——
隐藏是「别再推给我」，不是「删了它」，详情/翻译仍要能打开。
