# Round 23 · 设计师视角升级指南（v1.8.1）

> 目标：让「重译本段」的承诺更准确，让导入的正文更干净，让备份只包含当前内容。

## 1. 设计问题

### D1. 「重译本段」只承诺这一段（P1）

用户点的是「重译本段」，不是「重译整章并接受新术语」。如果实现把整章
标成新版本，等于替用户宣称「其他段落也更新了」，这是错误的状态表达。

**方案**：单段重译保留整章的配置/术语版本；只更新正文 hash、token、费用、
时间与未完成段列表。阅读器仍显示「术语已更新」横幅，直到用户整章重译。
不新增「部分更新」文案，避免信息过载。

### D2. 导入的正文应该是「可读文本」（P2）

注音是排版辅助，不是正文。导入后保留 `<ruby>` 的汉字、去掉 `<rt>` 假名，
符合读者对「正文」的预期。

**方案**：在 `stripHtml` 中先移除 `<rt>`/`<rp>` 节点，再处理换行与标签。
不改变段落结构、不合并行。

### D3. 备份是「当前数据」的快照（P2）

`.bak-*` 是导入时的安全副本，不是用户当前书架的一部分。把它打进备份会让
备份体积与隐私面双重膨胀，也让「备份里为什么有两份同样的书」变得难以解释。

**方案**：导出时过滤路径中的 `.bak-` 段；当前目录内容不变。
不新增「清理旧备份」入口（本轮不做）。

### D4. 不改的东西

- 阅读器横幅文案与位置；
- EPUB 导入流程、章节切分规则；
- 备份 UI、manifest 格式、校验逻辑；
- 任何颜色、字号、间距。

## 2. 验收

- [ ] 改术语后只重译一段：过期横幅仍在；整章重译后消失。
- [ ] `<ruby>漢字<rt>かんじ</rt></ruby>` 导入后正文是「漢字」。
- [ ] `<rp>` 括号不残留（`<ruby>東京<rp>(</rp><rt>とうきょう</rt><rp>)</rp></ruby>` → 「東京」）。
- [ ] 备份 zip 中不存在路径含 `.bak-` 的条目。
- [ ] 没有新增可见控件或文案。
