# Round 23 · 用户视角升级指南（v1.8.1）

> 基线：1.8.0（versionCode 59）。Round 22 修了重复导入覆盖数据。
> 本轮收尾三个「看起来小、实际会误导用户」的问题。

## 1. 用户真实会遇到的 3 个问题

### U1. 只重译一段，整章却显示「术语已更新」（P1）

用户改了术语「勇者 → 英雄」，进入第 5 章，只对第 3 段点「重译本段」。
重译完成后，整章的 `glossary_hash` 被写成新术语版本，过期提示消失；
但第 1、2、4 段仍然是「勇者」。

**用户感受**：提示没了，以为整章都换成了「英雄」，读下去发现前后不一致；
再想重译整章时，已经没有任何提示提醒他。

**本轮要求**：单段重译只改这一段的内容，不把整章标成「已应用新术语/新配置」；
过期提示保留，直到整章重译。

### U2. EPUB 导入后正文夹着注音假名（P2）

`stripHtml` 只去掉标签，不去掉 `<ruby>` 的注音节点。原文

```html
<ruby>漢字<rt>かんじ</rt></ruby>
```

导入后变成「漢字かんじ」，读者看到汉字后面重复一串假名。

**用户感受**：本地导入的日文 EPUB 正文很脏，翻译时还会把注音当成正文翻一遍。

**本轮要求**：移除 `<rt>` / `<rp>` 注音节点，保留 `<ruby>` 的基准汉字。

### U3. 备份文件越导越大（P2）

`BackupExporter` 只过滤文件名里带 `.bak-` 的文件，不检查**目录名**。
重复导入后产生的 `novels/<book>.bak-20260101-.../` 目录会被整个打进备份。

**用户感受**：备份从 200 MB 涨到 500 MB；上传网盘很慢，恢复也更久。
旧目录里的正文还会被一起上传，增加隐私暴露面。

**本轮要求**：导出时跳过任何路径中含 `.bak-` 的目录；备份只包含当前书目录。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 单段重译不掩盖整章过期 | 改术语后只重译一段，仍显示过期提示 |
| U2 | EPUB 正文无注音残留 | `<ruby>漢字<rt>かんじ</rt></ruby>` 导入为「漢字」 |
| U3 | 备份不包含旧目录 | `.bak-*` 目录不进入 zip |

## 3. 明确不做

- 不改术语表 UI、翻译流程、EPUB 排版。
- 不删除已有 `.bak-*` 目录（用户可自行清理）。
- 不改变备份格式与校验。
