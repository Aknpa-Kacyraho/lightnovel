# Round 25 · 用户视角升级指南（v1.8.3）

> 基线：1.8.2（versionCode 61）。全量审计后剩下三个「状态不一致」问题。
> 本轮修完后再做一次审计；若只剩设计权衡，就停止发版。

## 1. 用户真实会遇到的 3 个问题

### U1. 「进行中」筛选下点「重试全部失败」，没有反应（P2）

任务中心的「重试全部失败」按钮按**全部**未完成任务显示，但实际重试时只取
**当前筛选**下的任务。切到「进行中」后，列表里没有 failed/partial，
点击后什么都不会发生。

**用户感受**：按钮明明在，确认框也弹了，点「开始重试」却没有任务开始。

**本轮要求**：重试范围始终是全部未完成的失败/未译全章节，不受当前筛选影响。

### U2. 快速搜索时，翻译加载提示提前消失（P2）

发现页每次搜索都会触发卡片元数据翻译。旧搜索的翻译请求返回时，
即使已经不是当前搜索，也会把 `metadataLoading` 置为 false。

**用户感受**：新搜索还在翻译书名/简介，加载条已经消失；过一会儿内容才跳出来。

**本轮要求**：只有当前搜索的翻译请求能结束加载状态；旧请求静默丢弃。

### U3. 世界线重新生成失败后，章节与知识对不上（P2）

「重新生成最后一章」会先删除旧章节的知识，再生成新章节。如果最后保存分支
文件失败，旧知识没有恢复，新知识可能已经写入。

**用户感受**：重新生成报错，但世界线里的人物/事实变成了新章节的，正文还是旧的；
之后再生成会基于错误的知识。

**本轮要求**：保存失败时恢复旧知识，保证章节文件与知识文件一致。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 任何筛选下都能重试全部失败 | 「进行中」筛选下点击也有任务开始 |
| U2 | 加载提示与当前搜索一致 | 快速连续搜索，旧请求不关闭新请求的加载 |
| U3 | 世界线失败不留脏知识 | 保存失败后知识恢复为旧版本 |

## 3. 明确不做

- 不改任务中心筛选/分组 UI。
- 不改发现页搜索源与翻译服务。
- 不改世界线生成 prompt 与校验。
