# Round 25 · 设计师视角升级指南（v1.8.3）

> 目标：让按钮承诺与行为一致，让加载状态只属于当前搜索，让失败回滚干净。

## 1. 设计问题

### D1. 「重试全部失败」是一个全局动作（P2）

按钮文案没有「当前筛选」的限定。用户在「进行中」页面看到它，心理预期是
「把所有失败的任务重新排上」，不是「重试当前列表里的失败任务」（列表里
本来就没有失败任务）。

**方案**：动作范围与文案一致——始终取全部未完成任务；当前的筛选只影响
列表展示，不影响这个批量动作。不新增提示。

### D2. 加载状态属于「最新一次搜索」（P2）

旧请求的完成不应该改变新请求的加载状态。用户只需要看到「当前搜索还在
翻译」或「当前搜索已完成」。

**方案**：旧 token 的翻译请求直接返回，不修改 `metadataLoading`；
只有当前 token 的请求可以结束加载。视觉不变。

### D3. 失败必须回滚到操作前（P2）

世界线重新生成是一个「替换最后一章」的操作。失败后应该回到操作前的状态，
而不是留下「旧正文 + 新知识」的混合体。

**方案**：保存分支文件失败时恢复旧知识；错误提示沿用现有文案。
不新增确认框或进度 UI。

### D4. 不改的东西

- 任务中心筛选 chip、任务行、确认框；
- 发现页搜索框、结果卡片、来源筛选；
- 世界线页面结构、生成参数；
- 任何颜色、字号、间距。

## 2. 验收

- [ ] 切到「进行中」，点「重试全部失败」并确认：失败任务开始重试。
- [ ] 快速搜索 A→B：A 的翻译返回后，B 的加载条仍在，直到 B 完成。
- [ ] 模拟世界线保存失败：旧知识恢复，正文与知识一致。
- [ ] 没有新增可见控件或文案。
