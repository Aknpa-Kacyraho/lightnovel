## 用户视角

**已改善**

1. 手动加入的章节先于自动预译执行；点「翻译全书」后不会一直卡在当前阅读位置附近。
2. 同一章被重复请求时记为跳过，不再让任务中心的失败数虚增。
3. 点「暂停」立即取消当前请求，不再出现「已暂停但还在扣费」。

**仍然存在**

- 暂停后当前章可能留下 `partial` 状态，恢复时只补缺失段（预期）。
- 队列的 `completed` / `failed` 仍是队列生命周期累计值，新一批任务不会清零。
- 无法在 UI 上区分「跳过」与「未处理」。

## 设计师视角

**一致**

- 没有新增/删除控件或文案。
- 暂停、恢复、停止仍使用现有按钮与进度卡片。
- 失败数只在真实失败时增加，统计更可信。

**取舍**

- 没有为「跳过」增加单独计数：用户只需要知道没有失败。
- 没有调整队列卡片的信息层级：本轮只改行为。

## 工程师视角

**做对了**

- 出队顺序抽成 `pickNextIndex`，手动优先，自动计划不会丢失。
- 结果归类抽成 `dispositionOf`，四种结果明确；`SKIPPED` 不污染统计。
- `pause` 取消 worker 后，`finally` 的 `queue.worker === self` 保护仍然成立，
  不会重复清理或重启。
- 7 条纯 JVM 测试覆盖优先级与归类，不依赖 Robolectric。

**风险与限制**

- 手动优先期间自动预译暂停；手动队列清空后自动继续，不会漏章。
- `pause` 取消正在写的章节会产生 `partial`；已写入的段落缓存保留，恢复后只补缺失段。
- `retriedTargets` 在 `enqueue` 时不清空，之前失败过的章再次手动重试时不会自动重试第二次；
  这是保守策略，避免无限重试。

**未验证**

- 真机上暂停/恢复的实际时序与 token 停止。
- 长队列（数百章）下手动/自动切换的响应。
- 多本书同时排队时的 UI 表现。

## 结论

Round 20 目标达成，可作为 1.7.1 发布。术语过期检测留给 Round 21。
