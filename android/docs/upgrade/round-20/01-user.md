# Round 20 · 用户视角升级指南（v1.7.1）

> 基线：1.7.0（versionCode 56）。Round 19 修了失败出口与重译排版。
> 本轮修「翻译队列不听话」：手动任务被插队、重复任务被算失败、暂停不停。

## 1. 用户真实会遇到的 3 个问题

### U1. 点「翻译全书」，进度却一直停在前几章（P1）

阅读器会自动预译「当前章 + 后续几章」。这些自动目标在队列里**永远优先于**
用户手动点的「翻译全书 / 本卷 / 任务中心重试」。用户每滚动一次，自动计划
还会重建一次，手动章节继续往后排。

**用户感受**：明明点了全书翻译，进度条却一直在当前阅读位置附近打转；
想翻的后面几十章迟迟不动。

**本轮要求**：用户手动加入的章节优先于自动预译；手动任务清空后再回到预译。

### U2. 任务中心把「已经在翻的章」记成失败（P2）

队列里同一章可能被自动预译和手动重试同时选中。后到的任务发现「本章已有
任务在跑」，注册失败，但队列把它当成一次失败：

**用户感受**：明明正在翻，任务中心却显示失败 +1；停下来看，章节其实是好的。

**本轮要求**：重复任务算「跳过」，不计完成也不计失败，不写错误信息。

### U3. 点「暂停」后还在扣费（P2）

`pause` 只在队列空闲时取消 worker；如果正好有一章在翻，它会继续跑完。
界面已经显示「已暂停」，用户以为停了，实际还在请求 API。

**用户感受**：点了暂停，进度还往前走；费用也在涨。

**本轮要求**：暂停立即停止当前请求；已翻好的段落保留，未完成的章节保持可重试。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 手动任务先跑 | 同时存在手动/自动目标时，先处理手动 |
| U2 | 重复任务不算失败 | 重复注册不计入失败数 |
| U3 | 暂停立即生效 | 点暂停后当前请求取消，状态变暂停 |

## 3. 明确不做

- 不改自动预译的章数策略（仍由设置决定）。
- 不改任务中心的筛选与分组 UI。
- 不做跨书队列合并。
