# Round 20 · 设计师视角升级指南（v1.7.1）

> 目标：让「翻译队列」符合用户按下的按钮；交互与视觉不变。

## 1. 设计问题

### D1. 手动意图优先于自动行为（P1）

自动预译是系统替用户做的决定，手动翻译是用户明确下的指令。
两者冲突时，必须让手动指令先完成，否则用户会觉得按钮失灵。

**方案**：队列出队顺序改为「手动 → 自动」；不新增排队提示、
不改变现有进度卡片的信息层级。

### D2. 「正在翻」不是失败（P2）

同一章被两个入口同时请求时，用户看到的是「失败 +1」，但实际没有失败。
这会制造虚假的挫败感，也会让「重试全部失败」多翻一次。

**方案**：重复注册归类为「跳过」；完成数、失败数都不变。
任务中心现有的「进行中」状态足以表达真实情况。

### D3. 暂停必须是即时承诺（P2）

暂停按钮的语义是「现在停」。如果当前章继续跑几十秒，按钮就不可信。
已完成的段落已经写进缓存，取消不会浪费已花的钱。

**方案**：暂停立即取消当前请求并把状态切到暂停；恢复后从队列继续，
已缓存段落不会重复请求。

### D4. 不改的东西

- 任务中心布局、筛选 chip、重试按钮；
- 阅读器预译的触发时机与章数；
- 队列进度卡片文案；
- 任何颜色、字号、间距。

## 2. 验收

- [ ] 手动加入第 30 章、自动预译第 12–14 章：先翻第 30 章。
- [ ] 同一章被重复加入：失败数不变，没有新的错误提示。
- [ ] 翻译中点心暂停：请求停止，卡片显示暂停，不再新增 token。
- [ ] 恢复后继续剩余章节，已完成的章不重复请求。
- [ ] 没有新增可见控件或文案。
