# Round 16 · 设计师视角升级指南（v1.6.0）

> 目标：修复用户能感知的位置错位；不改变界面结构。

## 1. 设计问题

### D1. 位置语义要一致（P0）

阅读器有两个坐标系：

- **行号**：滚动列表的 item 索引（`chapterBlocks`），用于恢复滚动位置；
- **段号**：段落模型的索引（`Paragraphs.split`），用于分页锚点、书签、知识库。

UI 不需要知道两者区别，但**持久化只能存段号**。当前滚动模式把行号写进段号字段，
导致跨模式错位。

**方案**：
- `read_state.progress_block` 统一为段号；
- 滚动模式的 `scrollParagraph` 仍存行号（仅供列表 UI）；
- 两种模式切换时用映射函数换算，不改变任何视觉。

### D2. 书签预览必须来自当前段（P0）

预览取错段比跳转错更伤：用户看到书签写着别人的台词。

**方案**：`addBookmark` 在滚动模式用 `currentParagraphIndex()`（行→段映射），
预览与跳转都用同一个段号。

### D3. 跳转要有「到达感」（P1）

滚动模式下点书签/搜索结果，列表必须滚动到目标行。已经滚到目标位置时不要重复滚动
（会打断用户）。

**方案**：`LaunchedEffect(scrollParagraph)` 中比较 `listState.firstVisibleItemIndex`，
不同才 `scrollToItem`；不新增动画（避免长距离滚动过慢）。

### D4. 不改的东西

- 分页/滚动两套渲染；
- 书签/搜索 UI；
- 进度显示与页码；
- 数据库结构。

## 2. 验收

- [ ] 滚动读到第 3 段，切翻页再切回，仍在第 3 段。
- [ ] 滚动模式加书签，预览是当前段文字；点击回到当前段。
- [ ] 点书签后滚动列表立即到目标行。
- [ ] 已在该行时不重复滚动（不抖动）。
