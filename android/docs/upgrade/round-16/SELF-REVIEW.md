# Round 16 · 三视角自检（v1.6.0）

> 验证环境：Windows 开发机，Gradle 8.13，JDK 17，Android SDK 36。无真机（`adb` 不可用）。

## 结果摘要

| 项 | 结果 |
| --- | --- |
| JVM 测试 | **270 tests / 0 failures / 0 errors / 1 skipped**（+6 映射） |
| lint | **0 errors / 22 warnings**（无新增） |
| Debug 构建 | 成功，versionCode 53 / 1.6.0 |
| 数据 | 无 schema 变化；`progress_block` 语义统一为段号 |

## 用户视角

**已改善**

1. 滚动模式读到的位置，切翻页再切回来不会错段。
2. 滚动模式添加书签使用当前段落，预览与跳转正确。
3. 滚动模式下点书签/搜索结果，列表滚到目标行。

**仍然存在**

- 旧版本存进行号的历史进度没有迁移，首次恢复可能偏几段（一次性）。
- 跨章跳转仍只到章首（Round 17 修）。
- 滚动模式的页码/百分比仍是行号语义，显示不变。

## 设计师视角

**一致**

- 没有新增/删除任何控件，只修行为。
- 滚动列表跳转无动画（避免长距离滚动过慢）。
- 书签预览文字与当前段一致。

**取舍**

- 没有做「行号/段号」的可见提示，用户不需要知道两套坐标。
- 没有为旧数据做启发式迁移（无法可靠区分）。

## 工程师视角

**做对了**

- 映射逻辑从 ViewModel 私有方法抽成纯函数，正反向都有测试。
- 写进度、恢复、书签、翻译锚点四处统一使用段号。
- `lineForParagraph` 与 `paragraphIndexForLine` 往返测试通过。
- 滚动列表 effect 等值检查，避免与用户滚动互相触发。

**风险与限制**

- `paragraphIndexForLine` 假设 `paragraphs` 的文本行数与 `chapterBlocks` 一致；
  bilingual 模式下源/译拼接行数可能不同，映射是近似（已有实现同样假设）。
- 旧 `progress_block` 存行号的数据会导致首次恢复偏差；用户翻一页后即被新语义覆盖。
- `load()` 恢复时用到 `_state.value.displayMode`，若与 `paragraphs` 构建模式不一致，
  映射会偏差（当前同一次 load 内一致）。

**未验证**

- 真机上滚动跳转的实际落点与滚动动画。
- 超长章节（数千行）映射耗时（纯 Kotlin 线性扫描，可接受）。
- bilingual 模式下书签跳转的准确度。

## 结论

Round 16 目标达成，可作为 1.6.0 发布。加载竞态与跨章跳转留给 Round 17。
