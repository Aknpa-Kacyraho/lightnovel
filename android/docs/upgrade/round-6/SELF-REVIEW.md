# Round 6 · 三视角自检（v1.2.2）

> 验证环境：Windows 开发机，Gradle 8.13，JDK 17，Android SDK 36。无真机（`adb` 不可用）。

## 结果摘要

| 项 | 结果 |
| --- | --- |
| JVM 测试 | **220 tests / 0 failures / 0 errors / 1 skipped**（+5 `ReaderProgressTest`） |
| lint | **0 errors / 22 warnings**（`ClickableViewAccessibility` 仍为 0） |
| Debug 构建 | 成功，versionCode 43 / 1.2.2 |
| 数据 | 无 schema/迁移/备份变化 |

## 用户视角

**已改善**

1. 单击正文即可隐藏/显示顶栏与底栏；查询模式下点词优先，不会误触。
2. 底栏新增 2dp 本章进度线，翻页与滚动都随进度变化。
3. 书架「继续阅读」卡补了同风格进度线，信息密度与列表一致。
4. 第一次进入沉浸提示「单击正文或点下方按钮退出沉浸」，3 秒后消失。

**仍然存在**

- 单击正文的手感需要真机确认；查询模式关闭时，点任何空白都会切换。
- 没有「自动隐藏工具栏」选项（有意不做，避免猜测）。
- 点击左右区域翻页未做（Pager 滑动已够用）。

## 设计师视角

**一致**

- 进度线只有 2dp，透明度 0.28/0.45，不抢正文；没有圆角、没有阴影。
- 沉浸提示用 `labelSmall` + `secondaryColor`，不遮挡正文首行。
- 底栏结构与按钮顺序未变，只多了一条线。
- 继续阅读卡与列表卡使用同一「细线」语言，不是两种进度组件。

**取舍**

- 沉浸提示每次进入都出现（同一章重复进入也算）；没有做「只提示一次」的持久化，
  避免新增存储键。
- 没有给进度线加百分比文字：底栏已有页码，重复信息会增噪。

## 工程师视角

**做对了**

- 点击判定顺序明确：查询模式只处理词条，普通模式才切换沉浸；横向滑动由 `moved` 排除。
- `readerChapterProgress` / `shelfProgress` 是纯函数，0 值、越界、空章都有断言。
- 进度线用两个 `Box` 自绘，不依赖 `LinearProgressIndicator` 的默认停靠点，
  视觉可控。
- 沉浸提示由 `LaunchedEffect(immersive)` 驱动，退出立即复位。

**风险与限制**

- `ReaderPageView` 的手势没有 JVM 测试：`onCenterTap` 的真实触发依赖 Android View，
  只能靠 lint 与真机。
- `shelfProgress` 从 `feature.reader` 导入到 `feature.library`，是跨 feature 的纯函数依赖；
  若未来模块化，需要移到 `core`。
- 进度线 0.28 alpha 在夜间纸色下可能偏淡，必要时提高，不改结构。

**未验证**

- 真机单击、滑动、查询点词三者的实际互斥。
- 翻页/滚动进度线与页码的一致性（只有纯函数断言）。
- 沉浸提示的 3 秒时长与位置在刘海屏/横屏下的表现。

## 结论

Round 6 目标达成，可作为 1.2.2 发布。三轮（1.2.0–1.2.2）完成了本轮
「用户视角体验与视觉疲劳」的全部计划项。
