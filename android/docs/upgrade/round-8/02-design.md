# Round 8 · 设计师视角升级指南（v1.3.1）

> 目标：把「费用」从恐吓式提醒变成可判断的数字；把「过期」变成可信状态。

## 1. 设计问题

### D1. 过期提示必须可信（P0）

横幅「译文过期：模型/提示词更新」是用户决定要不要重译的依据。
单段重译后仍显示过期，会让用户重复花一次钱。

**方案**：修数据（见工程），UI 不变。验收时要在「改模型 → 只重译当前段」的
路径上确认横幅消失；整章重译仍保留版本存档。

### D2. 费用要「区间」而不是「可能」（P1）

**方案**：统一格式：

- `¥0.02–0.03`（区间，保留两位小数）；
- `< ¥0.01`（极小金额）；
- `约 ¥1.20`（单值场景，如已知 token 的实际费用）。

放置位置：
- 阅读器「更多 → 翻译本章（约 1200 字 · < ¥0.01）」——文字过长，改为
  第二行小字？菜单项只有一行。取舍：菜单里只保留字数，金额放**确认对话框**；
- 章节列表批量翻译确认：正文加一行「预计费用：约 ¥0.30–0.80」；
- 详情页范围翻译确认：同上；
- 阅读器单章翻译没有确认对话框，**不加金额**，避免每次点翻译都被数字打断。

### D3. 重试对用户不可见（P1）

自动重试不应弹提示、不应把状态从「进行中」改成「失败」再改回。
任务卡只显示最终结果；重试期间保持「正在翻译」。

**约束**：不改任务卡布局；`failed` 计数不因一次重试跳动。

### D4. 任务页上限（P2）

列表变长不改变视觉；只在超限时显示一行说明「仅显示最近 300 条」。
无新增按钮。

### D5. 一致性

- 所有金额用 `¥`，不用「元」；
- 预估文案以「约」开头，不写「预计花费」这种正式措辞；
- 确认对话框的主按钮不变（仍是「开始翻译」/「开始」）。

## 2. 验收

- [ ] 批量翻译确认框出现「预计费用：约 ¥…」，不挤压按钮。
- [ ] `< ¥0.01` 与两位小数格式都出现且不换行成三行。
- [ ] 单段重译后过期横幅消失。
- [ ] 自动重试期间任务卡不闪「失败」。
- [ ] 任务超过 300 条时出现说明文字。
