过程中修正了一处自己的估算错误：初版测试期望 10000 字显示 `¥0.02–0.04`，
实际 `0.035` 按 `%.2f` 输出 `0.03`；已改为断言 `¥0.02–0.03`，并同步修正文档里
「每千字 ¥0.02–0.05」的错误示例（实际默认价格下每千字 < ¥0.01）。

## 用户视角

**已改善**

1. 改模型/提示词后只重译一段，不再一直显示「译文过期」。
2. 翻译章节确认框显示「按每千字约 < ¥0.01 估算，实际以 token 计费」。
3. 阅读器「翻译本章」显示「（约 1.2 千字 · < ¥0.01）」。
4. 429/超时/503 等可重试失败，队列自动再试一次。
5. 任务页上限 300，旧失败不再被 100 条截断。

**仍然存在**

- 没有预算上限/账单；用户仍可能一次翻全书花掉未知金额（费用区间只在确认框）。
- 自动重试只针对队列（后台预译/批量），阅读器单章失败仍靠手动。
- 费用是估算，实际以 token 计费；文案已注明。

## 设计师视角

**一致**

- 费用文案统一「约 ¥…/ < ¥0.01」，不写「预计花费」；确认框主按钮不变。
- 自动重试不产生额外 UI 状态，任务卡不会先闪「失败」。
- 阅读器菜单标签变长，但仍是单行菜单项；过长时 `DropdownMenu` 会截断/换行，
  需真机确认。

**取舍**

- 没有在阅读器单章翻译前加确认框：多一次点击会打断阅读，费用已在菜单里给出量级。
- 批量确认只给单价，不给总额：在线书 raw 未下载，无法准确知道字数。

## 工程师视角

**做对了**

- `CostEstimator` 与 `TranslationConfig` 的默认价格共用常量，避免两处漂移。
- `formatCostRange` 固定 `Locale.US`，小数点在所有区域设置下一致。
- `shouldRetryAfterFailure` 是纯函数，队列只依赖它判断；每章最多一次。
- `TargetResult` 保留 `retryable`，不再把「不可重试」和「可重试」都当 false。

**风险与限制**

- 自动重试会增加一次 API 调用；已限制为可重试错误 + 每章一次。
- `translateTarget` 中「原文下载失败」被标为可重试（网络问题），会在队列里再试一次；
  若源站持续不可用，最终仍计失败。
- 费用估算的 token 比例是经验值，日文长句/中文短句可能偏差 30% 以内。

**未验证**

- 真机上菜单长标签的显示（「翻译本章（约 1.2 千字 · < ¥0.01）」）。
- 429 场景下自动重试的实际节奏与任务卡状态。
- 300 条任务列表的滚动性能。

## 结论

Round 8 目标达成，可作为 1.3.1 发布。书库彻底删除留给 Round 9。
