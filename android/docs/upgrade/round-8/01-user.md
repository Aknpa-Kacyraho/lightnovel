# Round 8 · 用户视角升级指南（v1.3.1）

> 基线：1.3.0（versionCode 44）。Round 7 修了书库重复与排序。
> 本轮只做翻译：**别让用户白花钱、别让过期提示骗人、失败能自己恢复**。

## 1. 用户真实会遇到的 4 个问题

### U1. 单段重译后，整章仍标「译文过期」（P0）

`TranslationService.retranslateParagraph`（`:163-172`）写回 sidecar 时没有更新
`translationConfigHash` / `modelProvider` / `modelId` / `promptVersion`。
`ReaderViewModel.staleReasons`（`:1153`）用 hash 比较当前配置，于是：

- 用户改了模型/提示词，只重译了一段；
- 阅读器仍显示「模型/提示词更新」的过期横幅，即使这段已按新配置翻译。

**用户感受**：我明明重译了，它还说旧；那到底哪段是旧的？

**本轮要求**：单段重译与整章重译写同样的配置指纹；重译后不再误报过期。

### U2. 翻译前只知道「可能产生费用」，不知道多少（P1）

批量翻译确认（`ChapterListScreen.kt:524-527`）只写「可能产生 API 费用」；
阅读器菜单只写「约 N 字」。用户无法判断「点下去是几分钱还是一顿饭」。

**用户感受**：不敢点全书翻译，怕账单。

**本轮要求**：批量确认、详情页范围翻译、阅读器「翻译本章」都显示
**预估金额区间**（如「约 ¥0.02–0.03」；千字以内显示「< ¥0.01」），
基于当前模型价格与字符数。不承诺精确，文案写「约」。

### U3. 翻译失败后只能手动重试（P1）

队列把失败章节计入 `failed`，不再尝试。可重试错误（429、超时、503）往往
第二次就成功；用户得回任务页逐个点。

**本轮要求**：队列对**可重试**失败自动再试一次；不可重试错误（未配置 Key、
余额不足、内容过滤）不重试。最终仍失败才计入失败数。

### U4. 任务页最多 100 条，旧失败会消失（P2）

`LibraryDao.observeActiveTasks` 固定 `LIMIT 100`。书多、失败多时，
较早的失败任务被挤出列表。

**本轮要求**：上限提到 300；不新增分页。任务页保持按更新时间倒序。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 单段重译不再误报过期 | 改配置 → 单段重译 → 无过期横幅 |
| U2 | 翻译前看到金额区间 | 批量/单章确认都显示「约 ¥…」 |
| U3 | 可重试失败自动再试一次 | 模拟 429 一次 → 最终成功 |
| U4 | 旧失败不被 100 条截断 | 上限 300 |

## 3. 明确不做

- 不做预算上限/月度账单（需要账本，Round 9 之后评估）。
- 不做翻译质量评分、不做模型自动切换。
- 不改费用币种（仍按 CNY 估算）。
