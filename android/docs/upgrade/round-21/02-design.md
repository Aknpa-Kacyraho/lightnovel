# Round 21 · 设计师视角升级指南（v1.7.2）

> 目标：让「过期提示」只在真正需要重译时出现；不新增任何界面元素。

## 1. 设计问题

### D1. 提示必须可信（P1）

「术语已更新，需要重译」是一个高成本提示：用户会照着去花钱重翻。
如果它每翻一章就出现一次，提示就贬值了，用户要么忽略真正重要的提示，
要么被误导反复重译。

**方案**：把「术语版本」从综合版本里独立出来。只有术语条目（原文、译名、
别名）变化才算过期；摘要、人物、风格更新不触发该提示。

### D2. 记录翻译时的事实（P1）

译文旁边应该记录「这段译文是按哪一版术语翻的」，而不是「翻译结束时
术语表是什么版本」。后者会让翻译期间的真实变更消失。

**方案**：新译文写入独立的术语版本；翻译完成后的版本追平只更新
「上下文版本」，不覆盖术语版本。

### D3. 缓存不能把「半份结果」当完整（P2）

元数据翻译缓存以「有中文标题」为完成标准，简介缺失也被当成完成。
用户看到的是标题中文、简介原文，认知不一致。

**方案**：源简介非空时，缓存简介也必须非空才算完成；否则重试。
不新增「简介翻译中」的 loading，保持现有静默后台行为。

### D4. 不改的东西

- 术语表、人物卡、风格设置的界面；
- 阅读器过期横幅的文案与位置；
- 元数据翻译的字段与展示；
- 任何颜色、字号、间距。

## 2. 验收

- [ ] 只生成新章节摘要：旧章节不出现「术语已更新」。
- [ ] 修改术语译名：所有使用旧术语的章节出现「术语已更新」。
- [ ] 翻译中改术语：该章完成后仍提示过期。
- [ ] 标题已有、简介为空：再次进入详情页会请求并补上简介。
- [ ] 没有新增可见控件或文案。
