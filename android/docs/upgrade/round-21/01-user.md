# Round 21 · 用户视角升级指南（v1.7.2）

> 基线：1.7.1（versionCode 57）。前两轮修了失败出口、重译排版与队列控制。
> 本轮修「翻译过期提示」：它现在几乎每翻一章就误报一次。

## 1. 用户真实会遇到的 3 个问题

### U1. 每翻完一章，以前所有章节都提示「术语已更新」（P1）

翻译完成一章后会自动生成章节摘要，书的 `story.json` 随之变化。阅读器把
「术语表 + 人物 + 风格 + 摘要」混成一个版本号，用它判断译文是否过期。

**用户感受**：刚翻完第 10 章，回去看第 3 章，顶部出现「术语表或人物已更新，
当前译文需要重译」；用户以为术语被改了，去重译，白花 API 费用。其实术语
一个字没动，只是摘要多了一条。

**本轮要求**：只有**术语表本身**变化才提示重译；摘要、人物、风格变化
不应让已翻译章节变成「术语过期」。

### U2. 翻译过程中改了术语，这一章反而不提示过期（P1）

翻译开始时读取术语表；翻译完成后代码会把章节的版本号「追平」到当前
`story.json`，即使这一章用的是旧术语。

**用户感受**：翻到一半去改了术语表，回来发现刚翻的章节没有任何过期提示，
但正文里还是旧译名；再翻下一章才用上新术语，前后不一致。

**本轮要求**：章节记录的术语版本必须是**翻译时实际使用**的版本；
翻译完成后的追平不能覆盖它。

### U3. 书名有中文、简介是空的，简介永远不补翻（P2）

书籍详情页的元数据翻译有缓存：只要已有中文标题，就直接返回缓存。
如果上次模型只返回了标题、没返回简介，之后每次进入都认为「已翻译」，
简介一直是空的。

**用户感受**：书名是中文，简介一直是日文/空；怎么重进都不变。

**本轮要求**：源简介非空而缓存简介为空时，重新请求一次元数据翻译。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 摘要变化不再误报 | 只加摘要/人物，不出现「术语已更新」 |
| U2 | 翻译时术语版本可信 | 翻译中改术语，完成后仍提示过期 |
| U3 | 简介能补翻 | 标题已有、简介为空时重新请求 |

## 3. 明确不做

- 不改术语表 UI 与编辑流程。
- 不强制重译任何历史章节；旧数据行为保持原样。
- 不改元数据翻译的 prompt 与字段。
