# Round 30 · 设计师视角升级指南（v1.9.3）

> 本批设计师的职责不是配色，而是**失败路径与状态一致性**：
> 出错时界面不能骗人，不能留下坏东西，不能让用户卡在中间态。

## 1. 设计原则

### D1. 失败要「回到上一个好状态」，不是「停在坏状态」（P1）

看不见数据层的用户只会判断两件事：我的书还在不在、我读到哪了。
导入是「补齐」语义，任何字段的合成时间都不能比本机真实阅读时间更权威。
**规则**：备份没有状态文件 → 进度、收藏、移出状态全部保留本机；
备份有状态文件 → 按 `updated_at` 取新。

### D2. 中间态必须能被用户结束（P2）

「正在翻译」是一个有明确出口的状态：完成、失败、取消。
外部取消（任务中心、停止本书）也是合法出口，阅读器必须收到并退出转圈。
**规则**：任何 `running=true` 都必须有一条路径把它置回 false；
取消后横幅文案是「已取消」，不是继续显示进度。

### D3. 导出是原子承诺（P2）

用户看到「导出失败」时，不应该还要去文件管理器收拾残局。
**规则**：成功才留下文件；失败/取消删掉刚创建的目标；不删用户已有文件
（只处理 `CreateDocument` 新建的 URI）。

### D4. 容错优先于扩展名（P2）

文件扩展名是用户能改的，内容不是。EPUB 的判定应看 ZIP 文件头与
`mimetype`，而不是只信 `.epub`。spine 是阅读顺序的权威，单双引号都要认。

## 2. 验收

- [ ] 旧备份重复导入：进度、收藏、已移出状态不被回滚。
- [ ] 导出失败：目标文件不存在，错误提示明确。
- [ ] 任务中心取消后回阅读器：不再显示「翻译中」，可立即重新翻译。
- [ ] `.txt` 的 EPUB 能正常解析；单引号 `idref` 的章节顺序正确。
- [ ] 所有修复不改变正常路径的界面与文案。

## 3. 非目标

- 不改视觉 token、布局、动画。
- 不新增设置项或说明文字。
- 不为边缘情况增加弹窗；失败用现有错误条表达。
