# Round 32 · 设计师视角升级指南（v1.9.5）

> 本轮是数据恢复的收尾：**进度不能被“近似”改坏，完整不能被“部分”覆盖，
> 同一本书不能变成两份，旧备份也要有可读的目录。**

## 1. 设计原则

### D1. 进度是用户的锚点，不能用“看起来相近”的章节代替（P1）

`progressIdx in 1..size` 只对连续章节成立。章节号有缺口时，
回退到第 1 话并写入进度，会让用户失去真正的阅读位置。
**规则**：进度对应的 idx 存在就打开；不存在先补行/提示，不写回退章节。

### D2. 完整译文是资产，partial 是候选（P1）

partial 结果的语义是「这次没做完」，不是「这本书现在只译了一半」。
旧译文 complete 时，partial 只能作为失败提示，不能替换当前正文。
**规则**：complete 旧译文 + partial 新结果 → 保留旧译文，提示可重试。

### D3. 同一本书只能有一个身份（P0/P1）

`import_hash`、`source+sourceId`、`slug` 都是书的身份。
按 id 单键插入会让同一文件在库里出现两个身份，孤儿数据不可见。
**规则**：导入前按多键匹配；命中后把章节/进度/书签重映射到现有 id。

### D4. 旧备份也要能“看见目录”（P2）

没有 `data/chapters.json` 时，`episodes` 是唯一的章节数量线索。
在线书按 1..N 合成占位章节，至少让用户看到「这本书有 100 话」，
并能在打开时按需下载。本地书没有源站，不合成空章。
**规则**：online + episodes > 0 + 无元数据 → 占位章节，status = online。

### D5. 缓存是加速，不是真相（P2）

润色/单段修改后，旧缓存已不代表当前译文。
**规则**：修改正文的操作成功后 invalidate 该章缓存；下次整章翻译重新请求。

### D6. 筛选是一个整体状态，不能互相踩（P2）

清除筛选应该只清「造成空结果」的条件，不是把所有范围重置。
**规则**：只调用当前有值的 setter；保留 removedOnly。

### D7. 错误属于当前上下文（P2）

预览弹层的错误只属于当前这本书；打开另一本必须清空。
**规则**：`preview()` 清空 `previewError`；失败只在预览打开时设置。

## 2. 验收

- [ ] 章节 idx 为 1,2,3,50、进度 50：继续阅读打开 50，不打开 1。
- [ ] 完整译文 + partial 重译：正文仍是完整译文，横幅提示保留原译文。
- [ ] 同 import_hash 不同 id：导入后只有一本书，进度/章节/书签都在。
- [ ] 旧备份无 chapters.json：在线书显示 episodes 数量的占位章节。
- [ ] 润色后整章重译：请求重新发出，不直接拼旧缓存。
- [ ] 已移出 + 搜索无结果 + 清除：仍在已移出。
- [ ] 失败后打开另一本预览：没有上一本的错误。

## 3. 非目标

- 不做源站章节重排/删除同步。
- 不改备份 format；新文件仍可选。
- 不改阅读器 UI 结构。
