# Round 32 · 用户视角升级指南（v1.9.5）

> 基线：1.9.4（versionCode 68）。本轮收尾数据恢复的边界：
> 章节号不连续、旧备份、同文件不同 id、部分重译覆盖完整译文。

## 1. 用户真实会遇到的 5 个问题

### U1. 恢复后进度在第 50 话，但「继续阅读」打开第 1 话，并把进度改成 1（P1）

旧备份或部分恢复后，章节行是 `1,2,3,50`；进度是 50。
「继续阅读」用 `progressIdx in 1..chapters.size` 判断，50 不在 1..4，
回退到第 1 话；用户一滚动就把进度 50 覆盖成 1。

**本轮要求**：进度对应的章节存在就直接打开；不存在才回退，且不写错进度。

### U2. 已经完整的译文，重译只完成一半后变成「未译全」（P1）

用户对完整章节点重译；API 在几段后失败，部分段落保留日文原文，
结果把原完整译文覆盖成 partial。旧译文虽然在 cache 里，但 UI 没有恢复入口，
备份也不包含 cache。

**本轮要求**：旧译文是 complete 时，partial 结果不覆盖；提示「已保留原完整译文」。

### U3. 恢复后同一本书出现两份：一份有进度，一份是空壳（P1）

本机已有同一本地文件（id `local-bbb`），备份里是 `local-aaa`，
`import_hash` 相同。导入按 id 插入撞唯一索引，Room 静默跳过，
章节/进度/书签挂到不存在的 `local-aaa`，界面仍报「导入成功」。

**本轮要求**：按 `import_hash`/`source+sourceId`/`slug` 匹配现有书，
把章节、进度、书签合并到现有 id，不产生孤儿。

### U4. 旧备份（1.9.4 之前）恢复后，在线书仍只有已下载的几章（P2）

旧备份没有 `data/chapters.json`；恢复时只能按 `novels/` 文件建章节。
书有 100 话但只显示 5 话，剩余无法下载。

**本轮要求**：没有章节元数据时，按 `episodes` 合成 1..N 占位章节，可后续下载。

### U5. 润色/单段重译后，再点「重译本章」又退回润色前的旧译文（P2）

翻译缓存按「原文 hash + 配置 hash」命中；润色/单段修改后缓存没失效，
下次整章重译直接拼旧段落，把润色结果覆盖掉。

**本轮要求**：润色/单段重译成功后清掉该章翻译缓存，下次重译重新请求。

### U6. 「已移出」+ 搜索无结果，点「清除筛选」仍被踢出已移出（P2）

1.9.4 改了空态文案，但清除按钮先调用 `setFavoritesOnly(false)` / `setShelf(null)`，
这两个方法无条件把 `removedOnly` 置 false，用户仍回到全部书。

**本轮要求**：只清真正有值的筛选条件，保留「已移出」。

### U7. 预览加书失败后，再打开另一本书仍显示上一本的错误（P2）

`previewError` 只在加书开始/关闭弹层时清空；从列表行内加书失败后再打开
另一本预览，会看到不属于这本书的红色错误。

**本轮要求**：打开任何预览时清空旧错误；错误只属于当前预览。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 进度不丢 | 非连续 idx 的进度直接打开，不写回错误章节 |
| U2 | 完整译文不被降级 | complete + partial 结果保留旧译文 |
| U3 | 不产生重复/孤儿书 | 同 hash/source/slug 合并到现有 id |
| U4 | 旧备份目录完整 | 在线书按 episodes 合成占位章节 |
| U5 | 润色结果不被缓存回滚 | 润色/单段后缓存失效 |
| U6 | 清除筛选保留已移出 | 只清有值的条件 |
| U7 | 预览错误不串书 | 打开预览时清空 previewError |

## 3. 明确不做

- 不改备份 format 版本；`data/chapters.json` 仍是可选。
- 不做源站目录自动同步/重排。
- 不改视觉 token、导航结构。
