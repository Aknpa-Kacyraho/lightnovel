# Round 3 · 用户视角升级指南（v1.1.1）

> 基线：1.1.0（versionCode 39）。前两轮解决了误触、无障碍、空态、菜单与备份路径。
> 本轮处理「读久了才会遇到」的问题：大字体、横屏、长章节、翻译费用预期。

## 1. 用户会遇到的剩余问题

### U1. 大字体用户：按钮和卡片开始挤（P1）

系统字体 1.3x / 1.5x 时，书架空态的两个次级入口、任务卡的四个动作按钮、
设置页的筛选 chip 都可能换行或被压缩。当前没有 `FlowRow` / 自动换行策略。

**要求**：这些行在 1.5x 下不截断文字、不出现半截按钮；按钮可以换行到第二行。
验收用 Android「字体大小 最大」+ 显示大小「最大」。

### U2. 横屏阅读一行太长（P1）

阅读器 `StaticLayout` 按屏幕宽度排版。平板或横屏下，一行可能 40–50 个汉字，
眼睛回扫困难；左右边距仍按手机比例。

**要求**：阅读区域最大宽度限制在约 680dp（可读行宽），居中显示；
左右留白随屏幕增大，字号与行距设置不变。手机竖屏行为不变。

### U3. 翻译前不知道会翻多少章（P1）

详情页「翻译章节…」有费用确认，但章节列表与阅读器的「翻译本章」只显示动作，
不显示将产生多少章/多少字。用户点下去才知道要等多久。

**要求**：阅读器菜单「翻译本章」在已配置端点时显示「翻译本章（约 N 字）」；
只有当前章，不预测后续预译（预译由设置控制，单独说明）。
章节列表批量翻译对话框在确认前显示「共 N 章」。

### U4. 长章节首次打开没有进度感（P2）

`ReaderViewModel` 分页在 `Dispatchers.Default`，但 UI 只有 `CircularProgressIndicator`，
没有「正在排版第 x/y 段」。超长章（数万字）会让用户以为卡死。

**要求**：首次分页超过 300ms 时显示「正在排版…」文字；分页完成立即消失。
不做百分比（无法准确估算），只给确定性文案。

### U5. 备份恢复后不知道恢复了什么（P2，记录）

导入完成后只显示书籍数量。用户不知道阅读进度、译文、世界线是否一起回来。
**本轮记录，Round 4 候选**：导入结果摘要（书 N 本、进度 M 条、译文 K 章）。

## 2. 本轮必须交付

| 编号 | 结果 | 验收 |
| --- | --- | --- |
| U1 | 1.5x 字体不截断 | 真机字体最大 + 截图 |
| U2 | 横屏行宽受限 | 平板/横屏模拟器 |
| U3 | 翻译前看到章数/字数 | 文案与数量正确 |
| U4 | 长章节有排版提示 | 打开超大章观察 |

## 3. 明确不做

- 不做双栏阅读、不做仿真翻页、不做 TTS 改造。
- 不改翻译模型、不改预译策略、不改备份格式。
- 不为横屏重做导航与底栏。
