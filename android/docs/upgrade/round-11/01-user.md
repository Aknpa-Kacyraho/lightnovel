# Round 11 · 用户视角升级指南（v1.4.1）

> 基线：1.4.0（versionCode 47）。Round 10 补了书签。
> 本轮处理「想找书中某句话」：书内搜索。

## 1. 用户真实会遇到的 4 个问题

### U1. 想找一句话，只能逐章翻（P0）

阅读器只有目录（章节列表），没有正文搜索。用户记得「那句话」或某个设定名，
却不知道在第几章。

**用户感受**：一本 300 章的书，找一句话要翻半小时。

**本轮要求**：阅读器「更多」加「搜索本书」；输入关键词，在当前书的章节正文里搜索，
显示命中的章节、片段与前后文，点击跳转。

### U2. 搜索结果要能定位到段落（P1）

只显示「第 12 章命中」还不够；用户需要看到匹配的上下文，并跳到那一页。

**本轮要求**：结果每条显示「章节标题 + 匹配片段（含高亮关键词）+ 前后各 20 字」；
同章点击定位到命中段落；跨章先跳到目标章，再从结果点一次。

### U3. 搜索不能卡住阅读（P1）

整本书扫描是 IO + 文本处理；不能阻塞 UI，也不能把整本书读进内存。

**本轮要求**：搜索在 IO 线程逐章进行；每章最多 3 条、总数 30 条；
输入停止 300ms 后再搜；离开页面/取消输入立即取消任务。

### U4. 搜索范围要清楚（P2）

用户不知道搜的是原文还是译文。

**本轮要求**：当前显示模式是译文/双语时搜译文，原文模式搜原文；
结果页顶部标注「搜索范围：译文」/「原文」。没有译文的章节自动回退原文。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 能搜整本书正文 | 关键词命中多章，结果可见 |
| U2 | 结果有上下文并可跳转 | 同章定位到段落，跨章到章首 |
| U3 | 搜索不卡 UI | 输入防抖、取消生效、条数受限 |
| U4 | 范围明确 | 顶部显示译文/原文 |

## 3. 明确不做

- 不做正则、模糊匹配、拼音搜索。
- 不做跨书搜索（书库级搜索留给后续）。
- 不做搜索结果持久化/历史。
