# Round 26 · 用户视角升级指南（v1.8.4）

> 基线：1.8.3（versionCode 62）。最终审计发现一类跨模块问题：
> `runCatching` / `catch (Exception)` 把协程取消也吞掉了，导致「取消」不彻底。

## 1. 用户真实会遇到的 3 个问题

### U1. 取消翻译后，摘要/人物提取还在跑（P1）

翻译完成后会顺手生成章节摘要、抽取人物与知识。这些调用用
`runCatching { client.complete(...) }` 包住；用户返回书架/取消时，
`CancellationException` 被当成普通失败吞掉，协程继续往下写摘要和人物。

**用户感受**：已经退出阅读器，后台还在请求模型；流量/额度继续走，
下次进入发现书里多了几条「自动生成」的人物。

**本轮要求**：取消必须向上传播；取消后不再写摘要、人物或知识。

### U2. 快速切搜索，旧卡片的翻译请求还在跑（P2）

发现页的卡片元数据翻译同样用 `runCatching` 包住模型调用。用户换搜索词/
离开页面后，旧请求被吞掉取消，继续等 45 秒超时。

**用户感受**：切走了还在后台翻译，费用继续增加；返回时加载状态也可能不准。

**本轮要求**：取消直接结束请求，不再把结果写回 UI 或缓存。

### U3. 取消世界线生成，知识却写了一半（P2）

世界线差异报告、知识抽取的模型调用被 `runCatching` 包住；取消后
`getOrNull()` 返回 null，流程继续走到保存知识的分支。

**用户感受**：点了取消，分支没生成，但人物/事实列表多了几条；
再生成时模型基于这些半成品，前后矛盾。

**本轮要求**：取消时抛回上层，世界线生成/知识抽取的清理逻辑按取消处理。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 取消翻译后不再写摘要/人物 | 取消后知识点/摘要不新增 |
| U2 | 切搜索后旧请求结束 | 旧卡片翻译不再更新缓存/UI |
| U3 | 取消世界线不写半成品 | 取消后知识文件保持原样 |

## 3. 明确不做

- 不改网络层（OkHttp 的同步请求无法中途打断，仍会等当前请求返回）。
- 不改模型 prompt、重试次数、超时时间。
- 不改任何 UI。
