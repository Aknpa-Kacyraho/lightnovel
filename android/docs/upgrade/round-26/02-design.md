# Round 26 · 设计师视角升级指南（v1.8.4）

> 目标：让「取消」真的停止后续写入；没有界面变化。

## 1. 设计问题

### D1. 取消是一个承诺（P1）

用户按返回、切搜索、点取消，心理预期是「这件事停了」。如果后台继续
生成摘要/人物/知识，用户会在下一次进入时看到意料之外的变化，而且无法解释
这些内容从哪来。

**方案**：取消向上传播；所有「翻译完成后顺手做的事」在取消时停止。
不新增「已取消」提示，现有返回/取消按钮足够。

### D2. 费用必须可预期（P2）

旧搜索的卡片翻译继续跑，用户看不到进度，却继续消耗 API。这比「慢」更糟，
因为用户无法判断什么时候停。

**方案**：旧请求在取消/换 token 时立即结束；已完成的结果可以进缓存，
但不再触发新的模型调用。

### D3. 半成品比没有更糟（P2）

世界线取消后留下半套知识，会让后续生成基于错误前提。宁可什么都没有，
也不要「正文旧、知识新」。

**方案**：取消路径与失败路径一致：恢复/不写入知识；已有内容保持不变。

### D4. 不改的东西

- 阅读器、发现页、世界线的任何布局与文案；
- 加载指示与错误提示；
- 模型参数与网络超时；
- 任何颜色、字号、间距。

## 2. 验收

- [ ] 翻译完成后立刻返回书架：摘要/人物/知识不新增。
- [ ] 搜索 A→B：A 的卡片翻译取消，B 的加载正常结束。
- [ ] 世界线生成中点取消：分支与知识保持操作前状态。
- [ ] 没有新增可见控件或文案。
