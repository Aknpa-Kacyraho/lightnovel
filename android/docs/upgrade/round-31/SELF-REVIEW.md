## 用户视角

**已修复**

1. 恢复备份后，在线书保留完整章节列表，本地书保留章节标题。
2. 备份目录与数据库目录不一致时，新文件写入数据库现有目录，阅读器能读到。
3. 润色/单段重译/资料更新失败后，「重试」重试原操作，不再整章翻译。
4. 阅读器改字号/纸色后，设置页立即同步，不覆盖未保存的 Key/端点输入。
5. 已移出 + 搜索无结果显示「没有匹配的已移出书籍」，清除后仍在已移出。
6. 预览弹层内显示加书失败原因，可直接再点一次。
7. 目录选章后返回不再经过旧章节阅读器。

**仍然存在**

- 源站新增/重排章节不会自动进入现有书（需要后续目录同步）。
- 同一本地文件在两台设备生成不同 id 的备份，合并冲突仍按 id 处理（边缘场景）。
- 部分 SAF provider 不支持删除，导出失败仍可能留下空文件。
- 无真机：上述交互未在设备上逐条复现。

## 设计师视角

**一致**

- 恢复以「书的骨架」为准：章节表随备份走，文件只是正文。
- 重试与失败原因一一对应，用户不会因为点重试而触发更贵的操作。
- 设置页反映当前状态；空态区分「范围空」与「筛选空」。
- 错误出现在用户当前视野（预览弹层），返回栈符合「替换」直觉。

**取舍**

- 章节元数据只补空标题，不覆盖用户改过的标题。
- `storageDir` 不迁移旧文件，只保证新文件写到 DB 指向的目录；旧目录残留可后续清理。
- 目录替换 reader 后不能再从目录返回原章节，换取干净的返回栈。

## 工程师视角

**做对了**

- `BackupChapter` + `data/chapters.json` 是可选的；旧备份没有该文件时行为不变。
- `apply` 的章节合并是「现有优先、缺行补齐、空标题补全」，不会清空 token。
- `LibraryCommitter.commit` 的 `storageDirOverrides` 只改写入位置，source 仍用备份目录。
- `retryAction` 在各操作开始时清空、失败时设置、取消时清空；
  `retranslateParagraph` 补了取消处理。
- `SettingsViewModel` 持续 collect，首次加载 cache/hasKey，后续保留输入框。
- `emptyShelfCopy` 的 `hasFilter` 判断让空态顺序正确；清除按钮保留 removedOnly。
- `BookPreviewSheet(error)` 和 `popUpTo(reader)` 都是局部改动，未触碰导航结构。

**风险与限制**

- `data/chapters.json` 限制 8MB；超大书库会忽略该文件，书与进度仍恢复。
- `storageDirOverrides` 不迁移旧目录文件；如果旧目录有备份后新增的译文，
  它们仍在旧目录，阅读器不会读（已知限制，后续可做目录合并）。
- 设置 collect 不覆盖 `baseUrl`/`model`/`keyInput`；如果用户在设置页保存后
  阅读器又写 settings，设置页会同步阅读字段，端点输入保持用户值。
- `popUpTo(reader)` 会让目录成为新的栈顶；从目录返回直接回上级。

**未验证**

- 真机上的备份恢复（章节列表、标题）。
- 设置页与阅读器来回切换的实际刷新时机。
- 目录替换 reader 后的返回动画。

## 结论

Round 31 的 7 类修复落地，测试与 lint 通过。数据恢复路径从「书 + 进度 + 书签」
扩展到「章节骨架」；阅读器失败重试与设置同步也补齐。剩余为 P2/P3
（源站目录同步、唯一键合并、SAF 删除边界），不再影响核心数据完整性。
