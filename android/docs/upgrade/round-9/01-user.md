# Round 9 · 用户视角升级指南（v1.3.2）

> 基线：1.3.1（versionCode 45）。Round 7 修重复与排序，Round 8 修翻译一致性与费用。
> 本轮处理「书库只进不出」：能清理、清理前不误删、清理后后台不再跑。

## 1. 用户真实会遇到的 4 个问题

### U1. 移出的书永远占着空间（P0）

书架只有「移出书架」（`read_state.hidden = true`）：书、译文、世界线、进度全部保留。
读过的 50 本书移出后，本地文件一个不少。用户想清空间只能卸载 App（连没移出的也丢）。

**用户感受**：书架干净了，存储没干净；不敢卸载，也不敢留着。

**本轮要求**：在「已移出」视图提供**删除本地数据**：
二次确认，明确列出会删除「正文 / 译文 / 世界线 / 阅读进度」，
并提示「删除后无法恢复，建议先导出备份」。确认后删除文件与数据库记录。

### U2. 删除入口不能在在读的书上（P0）

如果在所有书卡上都放「删除」，手滑代价是整本书 + 译文。

**本轮要求**：删除入口只在「已移出」筛选下出现；
在读/想读/读完的书只能先「移出书架」，再删除。多一步，换安全。

### U3. 删除后后台任务可能还在跑（P1）

移出时 `LibraryViewModel.removeBook` 会取消下载与翻译 Job，
但预译队列（`ReadingTranslationCoordinator`）只在下一章开始前才检查 hidden。
删除后如果目录已消失，worker 会报「缺少原文」，制造无意义的失败记录。

**本轮要求**：移出与删除都显式停止该书预译队列；删除后任务页不再出现这本书。

### U4. 删除后没有反馈（P2）

**本轮要求**：删除成功 Snackbar「已删除《书名》与本地文件」；
删除失败保留书籍记录并显示错误，不静默。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 已移出的书可彻底删除 | 确认后书架、文件、章节记录都消失 |
| U2 | 删除入口只在已移出视图 | 在读列表无删除项 |
| U3 | 删除/移出后停止预译 | 任务页不再出现该书 |
| U4 | 删除结果有反馈 | Snackbar / 错误提示 |

## 3. 明确不做

- 不做批量删除、回收站、定时清理。
- 不删除备份、不删除 `data/` 全局数据。
- 不删除在线书的源站内容（只删本地缓存与记录）。
