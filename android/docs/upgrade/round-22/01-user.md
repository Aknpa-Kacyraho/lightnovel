# Round 22 · 用户视角升级指南（v1.8.0）

> 基线：1.7.2（versionCode 58）。本批继续修 bug，不加新功能。
> Round 22 修「重复导入备份把现有数据冲掉」——用户一旦误操作就会丢翻译
> 标题和阅读进度。

## 1. 用户真实会遇到的 3 个问题

### U1. 再导入一次旧备份，书名变回日文（P1）

导入备份时，代码对每本书执行 `@Upsert`：已存在的书会被**整行覆盖**成备份里
的值。备份是几个月前的，当时还没有中文标题/作者/标签。

**用户感受**：本来书架显示《再见爱丽丝》，导入备份后变回「さよならアイリス」；
标签没了，作者也没了。再导入一次更旧的备份，还会继续退化。

**本轮要求**：已存在的书保留现有非空字段；只有缺失的字段才用备份补。

### U2. 再导入一次旧备份，阅读进度倒退（P1）

`read_state` 也是整行覆盖。备份里保存的是三个月前的第 10 章，现在是第 50 章。

**用户感受**：打开书直接回到第 10 章；「在读」排序也乱了。
用户以为导入只是「补回丢失的书」，结果把现在的进度冲掉了。

**本轮要求**：进度按 `updated_at` 取较新的一方；收藏取并集；
已移出/隐藏状态保留现有。

### U3. 再导入一次旧备份，刚翻的章节文件消失（P1）

文件层更直接：`LibraryCommitter.commit` 发现目标目录已存在且内容不同，会把
现有 `novels/<book>` **整体移到 `.bak`**，再用备份里的旧目录替换。

**用户感受**：备份之后新翻译的第 11–20 章译文文件不见了；DB 里章节还标着
「已翻译」，点开却读不到中文。新下载的原文也可能一起消失。
同时章节行的中文标题、token 统计被旧备份的 null / 0 覆盖。

**本轮要求**：目录按文件合并，现有文件优先，只补备份里有、本地没有的文件；
章节行同样只补缺失。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 重复导入不退化书名/标签 | 二次导入后中文标题、作者、标签仍在 |
| U2 | 重复导入不回退进度 | 二次导入后仍在最新章节 |
| U3 | 重复导入不丢章节文件与信息 | 新译文/原文仍在；章节标题、token 保留 |

## 3. 明确不做

- 不改导入 UI、确认框与文案。
- 不改备份格式（仍兼容旧备份）。
- 不做「选择恢复哪一版进度」的高级合并。
