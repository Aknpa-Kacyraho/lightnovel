# Round 22 · 设计师视角升级指南（v1.8.0）

> 目标：把「导入备份」从「重置」改成「补齐」；界面与流程不变。

## 1. 设计问题

### D1. 导入的心理模型是「找回」，不是「回滚」（P1）

用户导入备份，通常是想找回丢失的书、章节或术语，而不是把整个书架恢复到
备份那一刻。无条件覆盖会惩罚「备份后继续使用」的用户。

**方案**：已存在的数据优先。书名、作者、标签、章节标题、token 统计只在
缺失时用备份补；不因为备份里是空值就清空现有多有内容。

### D2. 进度只能前进，收藏只能增加（P1）

阅读进度是用户最敏感的数据。旧备份的进度不应该覆盖新进度；
收藏是用户的明确意图，取并集比取备份值更安全。
已移出（hidden）是用户主动整理的结果，不应被旧备份改回。

**方案**：比较 `updated_at`，新的胜出；缺失时间戳时保留现有。
收藏 `existing || backup`；hidden 保留现有。

### D3. 章节与文件都是「增量恢复」（P1）

章节行承载翻译标题与费用统计，正文/译文文件承载用户真正阅读的内容。
两者都不能被旧备份整体替换。

**方案**：
- DB：按 `(bookId, idx)` 判断存在性；只插入缺失章节，已有章节一个字段都不动。
- 文件：目标目录已存在时不再整体替换；逐文件比较，只复制本地缺失的文件，
  现有文件（包括备份后新增的译文）保留。

### D4. 不改的东西

- 导入确认框、进度文案、结果摘要；
- 备份文件格式与校验；
- 解压到 staging 的顺序；
- 任何颜色、字号、间距。

## 2. 验收

- [ ] 第一次导入 → 改书名/章节名/进度 → 第二次导入同一备份：修改仍在。
- [ ] 第一次导入 → 新增一章译文文件 → 第二次导入：译文文件仍在。
- [ ] 备份里有、本地没有的章节文件会被补上。
- [ ] 备份进度比现有新：采用备份进度（真正的恢复场景）。
- [ ] 备份没有 `updated_at`：保留现有进度。
- [ ] 收藏取并集；已移出状态不被旧备份改回。
- [ ] 没有新增可见控件或文案。
