# Round 22 · 三视角自检（v1.8.0）

> 验证环境：Windows 开发机，Gradle 8.13，JDK 17，Android SDK 36。无真机（`adb` 不可用）。

## 结果摘要

| 项 | 结果 |
| --- | --- |
| JVM 测试 | **300 tests / 0 failures / 0 errors / 1 skipped**（+7） |
| lint | **0 errors / 22 warnings**（无新增） |
| Debug 构建 | 成功，versionCode 59 / 1.8.0 |
| 数据 | 无 DB schema 变化；备份格式不变 |

## 用户视角

**已改善**

1. 重复导入旧备份，已翻译的书名、作者、标签不会被空值覆盖。
2. 阅读进度按更新时间取较新的一方，旧备份不会把进度拉回去。
3. 已存在的章节保留中文标题、token 统计与模型信息；备份后新增的译文/原文
   文件不会被旧备份目录替换，缺失文件会被补上。

**仍然存在**

- 想用旧备份**回退**书名/标签/进度的用户会被保护逻辑阻止；没有「强制恢复」选项。
- 同名但内容不同的文件保留本地版本，备份里的版本不会覆盖；用户需手动处理。
- 备份中的 `.bak-*` 旧目录仍会被打进 zip（Round 23 修）。

## 设计师视角

**一致**

- 没有新增/删除控件、文案或 loading。
- 导入进度仍显示「校验备份 / 解压 / 提交文件 / 写入数据库」。
- 导入结果摘要数量不变；`merged` 计数只用于内部，不展示。

**取舍**

- 没有在导入确认框里解释「不会覆盖现有数据」：本轮先保证行为安全，
  文案留给后续版本评估。
- 没有为「旧备份进度被忽略」加提示：避免把内部合并规则暴露给用户。

## 工程师视角

**做对了**

- `mergeBook` 现有非空优先，保留 `importHash/local/source/sourceId`，`episodes` 取 max。
- `mergeReadState` 用 ISO-8601 字符串比较；备份无 `updated_at` 时保留现有；
  `favorite` 并集、`hidden` 保留。
- `missingChapters` 去重 + 只补缺失；`ImportCoordinatorTest` 第二次导入
  `applied.chapters == 0`。
- `LibraryCommitter.mergeDirectory` 只复制缺失文件，不移动/覆盖现有目录；
  首次导入仍整体移动；`sameTree` 快路径保留。
- 新测试覆盖：书合并 3 条、状态合并 2 条、章节过滤 1 条、目录合并 1 条、
  真实重复导入 1 条。

**风险与限制**

- `mergeDirectory` 复制的文件不参与 `rollback`；最坏是 DB 失败后留下几个
  新增文件，不会破坏现有文件。
- 书籍目录不再生成 `.bak-*`；用户若想回退某次导入，需要依赖备份 zip 或
  自己保留的副本。
- `updated_at` 为 null 的现有状态会被备份的新时间戳覆盖；这是「恢复旧备份」
  场景的预期行为。

**未验证**

- 真机上大备份（数千文件）重复导入的耗时。
- 合并目录在低存储空间下的失败表现。
- 备份导入后阅读器打开新增章节的实际表现。

## 结论

Round 22 目标达成，可作为 1.8.0 发布。EPUB 注音、单段重译版本字段与
备份 `.bak` 过滤留给 Round 23。
