## 用户视角

**已改善**

1. 打开在线书目录会自动检查源站；新增章节出现在目录末尾，并提示「新增 N 话」。
2. 「更多 → 同步目录」可手动刷新；无变化时明确提示「已是最新」。
3. 同步失败不影响已有目录阅读，只显示失败原因。
4. 源站少了几话，本地不删章节，已下载内容仍可读。
5. 任务卡显示翻译失败原因，重启后仍在；重试开始后旧原因消失。
6. 翻译中显示「已译 12/34 段」和一条细进度条；没有进度数据时不编造。
7. 完整译文遇到部分重译时，任务不再永久停在「正在翻译」，会显示失败原因。
8. 人物名在下划线之外有了链接语义，读屏可识别。
9. 目录/发现页底部弹层圆角与阅读器一致。

**仍然存在**

- 源站在中间插入或重排章节时，本地 idx 可能与正文错位；本轮只保证末尾追加。
- 源站已下架的章节不会自动删除。
- 自动同步每次进入详情会请求一次源站；离线时回退缓存但不会更新。
- 无真机：自动同步、失败原因、进度条、TalkBack 未在设备上逐项验证。

## 设计师视角

**一致**

- 目录同步延续「补齐不是重置」：只补缺失 idx，不改已有行、不删除、不重排。
- 反馈分层：自动同步只在有新增时提示，手动同步必有结果，失败不打断阅读。
- 失败原因与状态分离：状态徽章仍是一眼判断，原因是第二层信息。
- 进度克制：只有 `total > 0` 才出现进度条，避免假进度。
- 视觉 token 未扩张：颜色、字号、圆角全部沿用现有主题；没有新增卡片或描边。

**取舍**

- 新章节不自动下载、不自动翻译，避免流量与 API 额度意外消耗。
- 源站少章时选择「本地不缩短」，优先保护已下载资产，而不是严格镜像源站。
- 失败原因最多两行，长错误会截断；定位问题足够，不追求完整堆栈。
- 自动同步使用强制刷新换取「打开即新」，由失败回退缓存兜底。

## 工程师视角

**做对了**

- `planCatalogAppend` / `catalogEpisodeCount` 是纯函数，覆盖空库、尾部新增、源站缩水、
  稀疏 idx、空标题五类边界。
- `syncCatalog` 在单个 Room 事务内追加章节、补空标题、更新 `episodes`；
  已有章节的 `rawPath/zhPath/status` 完全不动。
- 手动同步的 `syncing` 防连点；标题翻译只针对新增章节，避免整本重翻。
- DB v6 只加可空列；`MIGRATION_5_6` 已注册到 `AppContainer.addMigrations`，
  `updateChapterTranslation` 统一清空旧原因，`markChapterFailure` 一次写状态与原因。
- partial 保护触发时现在会写 `failed + lastError`，修复了「永久正在翻译」的状态泄漏。
- 任务中心合并 `taskRegistry.active`，不改数据库即可显示段落进度。
- 阅读器改为 `LinkAnnotation.Clickable`，用 `rememberUpdatedState` 保证富文本缓存不因回调重建。
- 4 个非阅读器 Sheet 统一 20dp；lint 无新增 warning。

**风险与限制**

- 若源站重排/中间插入，`idx` 仍是位置而非稳定 ID；本轮不解决，文档已标注。
- `detail(force = true)` 每次进入详情都打一次源站；限流时只能回退缓存。
- 失败原因不进入备份；恢复后旧失败任务只保留状态，不带原因。
- Room v5 → v6 的迁移只由 JVM/Robolectric 测试覆盖，未在真实安装升级路径上验证。
- `LinkAnnotation` 的 TalkBack 播报未在设备上验证。
- 新增的 `last_error` 列会让 v6 数据库无法被 v1.9.5 及更早版本直接打开；
  回滚需要恢复数据库或降级 schema。

**未验证**

- 真机上的自动同步、断网回退、Snackbar 提示。
- 长目录（数千章）同步与标题翻译的耗时。
- TalkBack 对人物链接的播报与链接导航。
- 4 个 Sheet 在横屏/平板上的实际视觉。

## 结论

Round 33 完成了源站目录追加、失败原因持久化、任务进度、partial 状态泄漏修复，
以及两项无障碍/视觉一致性收尾。测试、lint、构建均通过；剩余问题集中在源站重排、
真机验证与旧目录迁移，属于 P2/P3，不影响本轮交付。
