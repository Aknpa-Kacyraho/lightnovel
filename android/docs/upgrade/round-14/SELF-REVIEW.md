## 用户视角

**已改善**

1. 术语表可按原文/译名/别名搜索，清空恢复全部。
2. 标题显示「共 N 条」；搜索时显示「N / 总数」。
3. 输入已存在的原文时，保存前提示「将覆盖译名」。
4. 删除术语先确认，并说明相关章节会标记过期。

**仍然存在**

- 没有术语导入/导出；旧词库导入仍在。
- 没有按章节/使用次数过滤。
- 搜索只在当前书术语表内，不跨书。

## 设计师视角

**一致**

- 搜索框与术语表单同宽、同描边；不新增颜色。
- 覆盖提示用 `tertiary`，不与错误红混淆。
- 删除确认「删除」用 error 色，「取消」在右。
- 条数行用 `labelMedium`，不抢标题。

**取舍**

- 搜索框放在说明之后：说明是术语表的使用前提，先读再搜。
- 没有做「搜索结果高亮」：术语条目短，命中即可见。

## 工程师视角

**做对了**

- `filterGlossary` 纯函数，空查询返回原列表（不复制、不排序）。
- 覆盖判断在 UI 层，保存逻辑不变，避免行为分叉。
- 删除确认只包 UI，`onDeleteGlossary` 仍是唯一删除入口。
- 测试覆盖原文/译名/别名/大小写/空查询/无命中。

**风险与限制**

- `duplicate` 用 `equals(ignoreCase = true)`，日文假名大小写不敏感影响极小。
- 搜索在内存过滤，术语上千条时每次输入全量扫描；当前规模可接受。
- 删除确认增加一步，但避免误删导致的过期标记。

**未验证**

- 真机上术语表搜索的键盘遮挡（页面可滚动，风险低）。
- 长术语名在列表中的换行表现。
- 覆盖提示在 1.5x 字体下的排版。

## 结论

Round 14 目标达成，可作为 1.5.1 发布。布局简洁化留给 Round 15。
