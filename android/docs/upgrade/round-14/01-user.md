# Round 14 · 用户视角升级指南（v1.5.1）

> 基线：1.5.0（versionCode 50）。沉浸与阅读器去杂已完成。
> 本轮处理「专有名词」：术语表要能找、能改、删之前知道后果。

## 1. 用户真实会遇到的 4 个问题

### U1. 术语表一多就找不到（P0）

`StoryMemoryScreen.kt:246-254` 直接 `forEach` 列出全部术语。翻译几十章后，
自动抽取的人名/地名/组织可能有上百条，找「某个角色」只能一路滚。

**用户感受**：想改一个译名，翻了半天；最后干脆不改。

**本轮要求**：术语表顶部加搜索框，按原文、译名、别名过滤；空结果给提示。

### U2. 重复保存会悄悄覆盖（P1）

`StoryMemoryViewModel.saveGlossary` 对同一 `source` 是「过滤旧的再加新的」。
如果用户手滑把「アリス → 爱丽丝」改成「アリス → 艾莉丝」，不会提示，
后续章节的锁定译名直接变了。

**用户感受**：不知道刚才那一下是新增还是覆盖。

**本轮要求**：输入原文已存在时，保存按钮上方显示「已存在同名术语，保存会覆盖译名」。

### U3. 删除术语没有后果提示（P1）

术语被删除后，相关章节会被标记过期，后续翻译不再锁定该译名。
当前点「删除」立即生效。

**本轮要求**：删除前二次确认，文案说明「删除后相关章节会标记过期，译名不再锁定」。

### U4. 术语表没有总数（P2）

**本轮要求**：列表标题显示「共 N 条」；搜索时显示「N / 总数」。

## 2. 本轮必须交付

| 编号 | 用户结果 | 验收 |
| --- | --- | --- |
| U1 | 术语可搜索 | 原文/译名/别名都能命中，清空恢复全部 |
| U2 | 覆盖前有提示 | 同名原文时显示提示 |
| U3 | 删除有确认 | 取消不删，确认才删 |
| U4 | 有总数 | 「共 N 条」/「N / 总数」 |

## 3. 明确不做

- 不做术语导入/导出（旧词库导入已存在）。
- 不做术语使用次数统计、按章节过滤。
- 不做自动术语合并（一致性检查已存在）。
