# 1.0.1 翻译体验返修

目标版本：Android `1.0.1` / versionCode 35（GitHub 发布版）。

## 这版解决什么

1.0.0 的翻译只是“能用”，但不像人用的：
- 后台预译完全看不见，用户不知道系统在花钱翻译哪一章。
- 打开正在翻译的章节会误显示“翻译失败”。
- 翻到下一章可能复用上一章的 raw 缓存，出现“顶部已译、正文日文”。
- 手动入口只有“当前章”，没有范围、进度和退出后的持续性。
- 所有分块都失败时仍写成 partial 原文，用户以为翻译成功。
- 任务中心只能逐条跳阅读器重试，取消一章后队列还在继续。

## 状态与队列

- `TranslationTaskRegistry` 增加：
  - `active: StateFlow<Map<String, TranslationTaskSnapshot>>`：当前任务和 `done/total` 进度。
  - `events: SharedFlow<TranslationTaskEvent>`：完成、取消事件。
  - `reportProgress`：翻译分块时更新进度。
  - 所有入口改为 `CoroutineStart.LAZY` 先注册再启动，避免重复点击抢任务。
- `ReadingTranslationCoordinator` 重写为按书排队：
  - 自动目标和手动目标分开保存；新窗口不再取消正在翻译的任务。
  - 同一本书只允许一个 worker，目标去重、顺序执行。
  - `pause(bookId)` / `resume(bookId)` / `stop(bookId)`。
  - 在线书缺少 raw 时先调用 `DirectLibraryService.ensureChapter` 拉正文。
  - 单章失败记录 `lastError`，继续处理后续章节。
  - 成功、失败、下载失败都会发出章节变更事件，章节列表即时刷新。
- 阅读器手动翻译改用 App 级 scope：离开章节或返回目录不会静默取消，任务仍可在任务页取消。
- 自动翻译打开原始模式时暂停，避免用户看原文还被计费。

## 阅读页

- 翻译状态从按钮缝里的一行小字改为独立状态条：
  - 当前任务进度、取消；
  - 失败原因、重试、关闭；
  - 未翻译时直接“立即翻译”；
  - 后台预译的章节、完成数、失败数、剩余数，支持暂停/继续/停止。
- 顶部状态点在后台任务运行时显示翻译中。
- 成功提示 6 秒自动消失，错误保留到用户关闭或重试。
- 手动菜单按状态显示“翻译本章/重译本章”；未译章禁用“润色本章”。
- 部分翻译的章节在双语模式不再把原文重复显示成译文。

## 作品详情

- 顶部菜单“翻译章节…”打开范围选择：
  - 当前章；
  - 当前章及后续 N 章（1/3/5/10）；
  - 全书未译章节。
- 确认前显示预估章节数并提示 API 费用；全书翻译必须明确确认。
- 详情页顶部显示翻译队列卡片：当前章、已完成、失败、剩余，可停止。
- 翻译成功后章节状态立即更新，不需要离开再回来。
- “未译全”章节纳入“失败/未译全”筛选。

## 任务中心

- 失败/未译全任务支持原地重试，不再强制跳阅读器。
- “重试全部失败”带费用确认。
- 分组显示该书的翻译队列，支持“停止本书”。
- 后台预译尚未产生任务行时，空态会提示队列正在运行。

## 正确性

- `ChapterTranslator` 所有分块都失败时返回 `Failed`，不再提交原文为 partial。
- 汉字/符号短句（如「食欲、睡眠欲、性欲。」）即使译文与原文相同也接受，不再把整章卡成 partial。
- `ReaderViewModel` 读取缓存时对照实际 zh 文件；缓存为 raw 但译文已存在则丢弃重建。
- 后台任务完成/失败/取消都会通知当前阅读器清缓存并重载。
- 翻译后生成故事记忆/知识时，同步 sidecar 的 story/glossary revision 和配置指纹，避免刚翻完就弹出“术语表已更新，需要重译”。
- 取消后的自动任务不会在重载时立刻重新启动。
- 部分章节的 `hasTranslation` 页面语义保留，但状态条和章节信息明确显示未译全。
